# 金融智能客服数字人产品需求文档 V1.3

本产品面向银行个人客户和企业客户，提供公开知识咨询、正式业务路径引导，以及在银行认证和授权后按包开通的只读查询。完整产品保留文字、语音和数字人能力；数字人服务开通后，用户始终可以选择文字模式。

本版基于八家银行的公开资料，提炼服务目录、对话导航、服务卡片、任务续接、网点导览、人工交接、跨渠道续接、财富知识分型、语音与数字人讲解、问题反馈十项需求。第 1.6 节说明案例证据，第 4.8 节区分新增与细化，第 20.4 节给出 24 条增量验收场景。

首轮五项确认继续有效：通用银行场景、个人与企业文字核心链路、仅非敏感演示资料、脱敏会话自创建起本地保存 7 天、付费调用和云费用为 0。建议下一开发切片只纳入六类既有演示主题的目录、导航与公开卡片，具体开发安排由阶段文档承接。

当前已完成 V1.2 的本机代码修订及 96/96 自动化测试；真实模型和产品经理体验/样例验收仍待验。本次交付为 PRD 文档修订，V1.3 增量尚未实现，不能沿用既有通过数宣告新版功能通过。V1.1、V1.2 原文保留。

## 2 产品定位与目标

### 2.1 服务定位

产品承担银行业务信息解释、办理路径引导和经授权的只读查询。数字人以清晰、稳重的形象辅助客户理解流程；服务开通后，客户可随时选择文字模式或请求人工；人工连接、排队及替代渠道状态以真实服务返回和银行配置为准。

业务结果由银行正式系统和人员给出。对话中的说明、模拟测算、业务入口跳转和查询结果属于不同服务状态，需要在界面与回复中区分。客户说“帮我转账”或点击业务入口，不构成已完成转账。

### 2.2 产品目标

1. 为个人与企业客户提供可理解、可追踪的银行咨询答案与办理路径。
2. 使用经过审核的知识和银行业务接口，减少过期、错误和无来源的回答。
3. 让客户在权限允许的情况下查询本人或授权企业的信息，防止跨个人、跨企业和跨角色读取。
4. 遇到紧急账户问题、疑似诈骗、复杂争议和投诉时，及时提供官方处理路径并交接人工。
5. 保留文字、语音、适老与无障碍路径，使数字人展示不成为获取服务的必要条件。

本版不承诺具体业务增幅、自动解决率或节省成本数值。指标目标需结合银行现有基线制定。

### 2.3 核心业务原则

| 原则 | 业务要求 |
| --- | --- |
| 信息来源清楚 | 利率、费率、产品规则和办理条件来自银行生效知识或权威系统 |
| 查询先确认权限 | 登录、客户归属、企业关系、角色与业务范围由服务端验证 |
| 咨询与办理区分 | 查询不改变资产或账户状态，办理入口进入银行既有流程 |
| 个人与企业隔离 | 身份、账户、历史、工具结果及播放队列按当前服务对象隔离 |
| 不确定时提供路径 | 无依据、冲突、过期或接口失败时说明当前无法确认，并给出官方查询或人工路径 |
| 紧急处理优先 | 账户安全和疑似诈骗提示先于普通口播、欢迎语和推广引导 |
| 人工服务可达 | 客户主动要求人工时直接进入承接流程，不要求完成数字人互动 |

### 2.4 首轮目标与完成口径

首轮用于核对个人/企业分流、演示来源、服务状态真实性、敏感输入保护及本地会话恢复。规则演示与真实模型验证分别验收；缺少真实模型冒烟和样例评价时，阶段 2 保持待验。

首轮不开展金融测算，不提供模拟余额、模拟账单或虚构办理结果。后续测算若要启用，需另行确认业务规则、假设、精度、风险说明与验收样例，由确定性计算产生结果。

## 3 用户与渠道

### 3.1 用户角色

| 角色 | 可获得的服务 | 限制 |
| --- | --- | --- |
| 未登录访客 | 公开产品说明、网点与渠道、办理材料、金融知识及安全教育 | 不查询任何客户账户、账单、贷款或企业经营数据 |
| 已认证个人客户 | 公开咨询；接口开通后查询本人授权范围内的信息 | 不查询他人账户；本人身份不自动赋予企业权限 |
| 企业授权查询用户 | 公开对公咨询及授权范围内的企业只读查询 | 以银行权限服务返回结果为准，不能仅凭企业名称或自述职务授权 |
| 企业经办人 | 获得办理步骤说明，进入银行企业渠道发起业务 | 不在聊天中提交支付、变更授权或完成审批 |
| 企业复核或审批人员 | 了解审批流程，进入正式渠道查看或办理 | 客服不代签、不代审批，不跳过企业既有控制流程 |
| 银行人工客服与客户经理 | 接收有权限的咨询摘要和交接信息，处理复杂业务 | 受岗位及企业服务权限约束 |
| 知识、业务、安全及审查人员 | 审核知识、渠道配置、运行记录与风险事件 | 分级授权，按职责访问数据 |

以上企业角色是设计上的典型角色，实际名称、分工和权限以目标银行系统为准。法定代表人、管理员或客户经理身份均不能代替接口权限校验。

### 3.2 渠道范围

首轮仅为本机浏览器验收工具，不接入手机银行、企业网银或开放 H5。银行试点候选渠道如下，正式接入组合、优先渠道及终端版本由目标银行评审后确定。

| 渠道 | 服务重点 | 一期建议 |
| --- | --- | --- |
| 个人手机银行 | 个人咨询、业务跳转、授权查询 | 首批候选；由银行选定试点渠道 |
| 企业手机银行或企业网银 | 对公咨询、企业权限识别、只读查询、经办路径 | 首批候选；不要求与个人渠道同步接入 |
| 银行官方网站 H5 | 公开知识、网点、材料与人工路径 | 可接入公开咨询 |
| 其他渠道 | 第三方平台、营业厅设备、远程柜面等 | 单独评审身份、安全与渠道适配 |

公开 H5 不因用户输入手机号、卡号或企业名称而获得认证状态。各渠道共享经审核知识，认证凭证、数据权限和允许功能按渠道配置。

### 3.3 首轮验收对象与身份

首轮验收者为本机单人产品验证人员，通过个人/企业服务选择模拟两类咨询语境。该选择不代表银行客户认证、企业成员身份或账户权限。

本机会话归属凭证仅用于阻止其他浏览器凭空读取本机会话，不能作为正式银行认证方案。扩大到联网多人试用之前，必须先形成可信登录、服务端用户隔离与试用范围方案。

## 4 分批交付范围与开通条件

### 4.1 业务能力分层

| 层级 | 能力 | 银行完整产品范围 | 开通条件 |
| --- | --- | --- | --- |
| A 公开咨询 | 审核 FAQ、产品与流程说明、网点渠道、安全教育、人工引导 | 必交付，个人和企业同时覆盖 | 银行提供并审核知识、渠道与服务入口 |
| B 授权只读查询 | 账户概况、信用卡账单摘要、贷款状态、企业结算状态等 | 条件交付，按接口逐项开通 | 认证、权限、数据接口、安全卡片、数据处理流程均通过评审 |
| C 正式业务入口与流程引导 | 转账支付、挂失冻结、开户、贷款申请、产品购买、企业审批的正式渠道入口 | 交付入口及说明，聊天不执行业务 | 在银行正式页面完成认证、确认、风控和必要审批 |

业务功能按 A、B、C 分层，防止某个查询接口尚未接入时整个银行客服无法落地。B 类未开通的场景仍提供 A 类说明和 C 类入口，不展示模拟余额或虚构状态。

### 4.2 完整产品必交付功能

下列要求保留完整产品目标，各项按交付包和银行开通条件分批验收；任何单个交付包通过均不代表完整产品交付。

1. 个人与企业服务选择、意图识别、业务目录及对应知识检索。
2. 经银行审核的答案、产品类型与风险提示、知识版本和无依据处理。
3. 文字输入、语音与数字人能力、暂停播放和适老显示。语音及数字人开通后由用户自主选用，不作为文字或人工服务的强制前置。
4. 公开知识与客户数据的权限分流，个人与企业上下文隔离。
5. 官方办理入口与客服队列配置，紧急问题路由、投诉与人工承接。
6. 数字人初始化、图文与口播关联、打断、刷新返回及异常降级。
7. 会话标记、脱敏记录、知识审查、评价和基本运营追踪。

### 4.3 条件交付的查询包

| 查询包 | 面向用户 | 范围 | 一期依赖 |
| --- | --- | --- | --- |
| 个人账户概况 | 已认证个人 | 本人账户状态、授权范围内的余额和近期记录 | 账户查询与归属接口 |
| 信用卡账单摘要 | 已认证个人 | 账单周期、银行定义的账单金额与到期日 | 信用卡系统及字段口径 |
| 个人贷款状态 | 已认证个人 | 申请状态、借款合同或还款计划的可查询字段 | 贷款系统及合同权限 |
| 企业账户概况 | 已授权企业用户 | 被授权账户范围内的账户状态、余额与摘要 | 企业身份、成员权限和对公账户接口 |
| 企业结算状态 | 已授权企业用户 | 已存在业务的银行受理、处理或结果状态 | 结算查询与回执状态接口 |
| 企业融资进度 | 已授权企业用户 | 企业名下申请进度和可披露材料状态 | 对公信贷流程与岗位权限接口 |

具体字段、刷新方式和金额展示方案需逐包确认。不能把“已登录”作为开通全部查询包的依据。

### 4.4 业务执行边界

聊天服务本期不直接执行资金划转、支付、还款、扣款、账户冻结或解冻、挂失解除、开户销户、企业授权变更、贷款审批、授信决策、投资产品交易或合同签署。

上述业务可提供正式办理入口。完整执行、客户确认、风险控制、授权与企业复核由既有业务系统承担。后续若扩展对话办理，应另立需求，不以本版入口功能作为已授权执行能力。

个人化投资推荐、自动信用评价、催收自动外呼、跨境结算办理、证券交易和银行代销保险销售不纳入本期。公开流程咨询中若涉及这些主题，只提供已审核的业务说明和官方承接路径。

| 对账与回单 | 企业如何对账；付款回单在哪里下载 | 对账流程、授权状态、受控的回单或对账入口 | 原始回单不作为普通附件发送至开放聊天 |
| 企业资金管理 | 多账户如何查询；现金管理产品有哪些 | 银行公开产品介绍、授权账户摘要、客户经理入口 | 不跨法人汇总资金，不自动调拨资金 |
| 企业融资 | 流动资金贷款材料、融资申请进度 | 审核条件、材料类别、企业授权后的进度信息 | 不承诺授信、担保豁免或审批结论 |
| 票据与贸易融资 | 票据业务步骤、贸易融资如何咨询 | 已审核的概念和业务路径，转接专业人员 | 一期不办理承兑、贴现或涉外交易；产品覆盖待确认 |
| 结算异常与企业争议 | 批次处理失败、回单缺失、扣费问题 | 授权状态说明、对公客服、工单受理 | 不根据模糊状态推断资金已划转或可重复提交 |

企业开户、网银、融资与结算制度均以目标银行为准。上述场景清单用于覆盖评审，不声称任一银行已提供全部产品。

### 5.3 场景服务约束

利率、费用、额度、截止时间、到账周期、贷款审批状态、风险等级等关键值不能由语言模型自行推断。公开问题读取银行生效知识；涉及客户合同与账户时读取授权接口；无数据时提供官方查询路径。

同一术语在个人与企业场景可能含义不同。用户提出“账户被冻结”“账单”“限额”或“贷款进度”时，先确认必要的服务类型和业务对象，再选择知识或接口；不要求客户在普通聊天中输入完整账户信息来消除歧义。

### 5.4 首批业务目录与知识准备

L0 的演示知识覆盖个人开户、存款流程、个人贷款流程，以及企业开户、对账/回单和融资流程，共六类样例主题。内容仅用来验证分流与来源，无真实利率、资格、费用或材料清单承诺。

| 范围 | L0 处理 | 银行试点处理 |
| --- | --- | --- |
| 六类演示主题 | 标记演示知识，按服务类型检索 | 由银行选择首批正式目录，提供并审核具体资料 |
| 其他第 5.1、5.2 节主题 | 无有效演示依据时明确不能确认 | 在业务负责人确认知识与正式路径后逐项纳入 |
| 余额/账单/私有进度 | 不查询、不显示示例数据 | 按 L3 查询包认证授权后开通 |
| 紧急、人工、投诉 | 测试优先级和真实未接入状态 | 正式入口、队列或替代路径通过检查后可对客开放 |
| 理财、代销、受限产品 | 不提供推荐、具体产品推介或测算 | 按第 7.9 节确认可见人群与允许内容 |

银行首批目录表需包含业务域、用户类型、具体主题、优先级、知识责任人、入口责任人、纳入交付包及资料就绪状态。本版不代银行指定产品、上线日或覆盖率目标。

### 5.5 服务目录与建议问题（CF01）

目录按照个人/企业、公开咨询/办理指引/授权查询/人工帮助分组，展示名称、适用对象、支持方式和当前可用状态。L0 仅显示第 5.4 节六类主题对应的演示咨询；未接入的查询与人工如需展示，只能显示说明入口，不出现“立即查余额”“正在排队”等误导动作。

每项目录由受控配置关联能力编号、知识编号及版本、允许渠道、适用对象、开关和按钮语义。名称相似不能代替这些关联；正式银行入口在 L2 由银行维护。选择目录进入相应咨询，不自动提交办理。

建议问题采用审核后的固定排序，正式知识须银行审核；L0 显示“演示问题”，不能声称银行审核。回答后最多显示 3 个与当前对象、主题及可用能力相符的问题，无合适内容可以不展示。没有统计依据不使用“热门第一”“最适合你”等标签；不读取资产、交易历史或客户画像。切换对象后重新计算推荐，知识失效或能力关闭后不再推荐。

### 5.6 网点与服务渠道导览（CF05）

正式试点可按用户主动选择的城市/区域、业务类型、个人/企业服务需求筛选银行提供的网点和渠道；不自动采集精确位置。网点结果包含名称、官方地址、适用业务、营业时段及例外说明、资料更新时间、可用的官方预约或咨询入口。

缺少对公服务资料时不能推定网点能办企业业务；缺少节假日/当日资料时不能承诺“今天营业”。无匹配结果或数据过期时说明无法确认，提供银行配置的人工/查询路径，不生成虚构网点。预约入口只表示可前往，预约成功须正式系统可信回执。

本项不列入下一 L0 开发候选，也不为演示采集位置。CF09 后续可以讲解同一网点卡片，不建立第二套网点数据。

## 6 身份认证与企业授权

### 6.1 服务状态

| 状态 | 允许功能 | 下一步 |
| --- | --- | --- |
| 访客 | 个人与企业公开咨询 | 需要客户数据时引导银行认证 |
| 个人已认证 | 本人权限范围内的已开通查询 | 进入企业服务时重新验证企业授权关系 |
| 企业身份已选但未授权 | 企业公开知识，不读取企业私有数据 | 通过银行企业身份与权限流程 |
| 企业授权有效 | 当前企业和角色范围内的已开通查询 | 每次查询验证账号、企业、账户和操作权限 |
| 认证过期或授权失效 | 停止私有查询，保留公开咨询及人工路径 | 重新认证，或由企业管理及银行渠道处理 |
| 人工接管 | 按坐席权限继续服务 | 自动回答停止，认证失效规则继续生效 |

认证状态由银行可信身份服务提供，不能从客户自述、上传图片、对话历史、roomid 或模型推理中产生。

### 6.2 认证流程

1. 判定问题是否需要客户私有数据。公开咨询不要求先登录。
2. 需要私有信息时说明查询用途，引导到银行受控认证页面或已有可信登录流程。
3. 银行认证成功后，服务端获取认证结果及业务权限所需的受控引用。
4. 查询网关校验当前用户、所属机构、个人或企业上下文、账户归属、角色与接口范围。
5. 查询结果按允许字段展示；缺少授权时不执行对应查询。
6. 每次查询和展示重新检查有效状态，客户端返回页面不能自动复用过期认证。

本版不在聊天组件内索取登录密码、交易密码、短信验证码、安全介质口令或卡片安全码。银行认证页面可按银行既有流程处理认证要素，凭证不进入语言模型、普通聊天记录、数字人口播或运营分析。

### 6.3 企业权限

企业授权至少需关联企业身份、操作者、角色、授权账户范围和可调用业务。实际属性及枚举以银行权限服务为准。

| 场景 | 处理规则 |
| --- | --- |
| 同一人拥有多家企业权限 | 查询前选择企业，展示当前企业，按当前授权账户范围处理 |
| 经办人请求未授权账户 | 拒绝私有查询，提供企业权限处理或对公人工入口 |
| 客户自称法定代表人或财务负责人 | 保留公开咨询，不据此提升权限 |
| 企业管理员权限变更 | 通过银行权限服务更新，失效结果即时影响后续查询 |
| 经办人询问审批业务 | 解释审批路径，跳转正式企业渠道，不冒充审批人 |
| 个人页面进入企业页面 | 清除旧业务上下文和结果，重新验证企业权限 |

企业是否设置双人复核、多级审批或单人办理，取决于银行与企业既有配置。本版要求保留既有控制流程，不把某一审批方式描述成适用于所有企业的统一法规要求。

### 6.4 切换与退出

切换个人和企业、切换企业、退出登录、认证过期或授权撤销时，立即停止相关口播和待播放队列，隐藏私有卡片，清除当前界面与运行缓存中的旧查询结果，作废未完成请求的展示资格。

会话可继续保留公开咨询，但私有数据的查询、历史恢复和再次展示必须重新校验当前上下文。审计记录按留存制度处理，与清除运行缓存分开。

## 7 知识与答案管理

### 7.1 知识来源

| 知识类别 | 允许来源 | 更新责任 |
| --- | --- | --- |
| 账户、卡、贷款和结算规则 | 银行已发布的业务制度与审核知识 | 对应业务部门 |
| 利率、费率、产品与活动 | 生效的产品资料、收费公示、权威服务接口 | 产品或业务部门 |
| 网点、营业时间和联系信息 | 银行渠道信息库 | 渠道运营 |
| 金融知识及防诈骗内容 | 经银行审核的公开教育材料 | 消保或专业业务部门 |
| 个人与企业数据 | 银行认证与授权范围内的业务接口 | 数据与业务系统团队 |

本期答案不依赖公开网络实时搜索为客户补齐业务数值，不把用户上传资料或聊天内容直接发布为银行知识。

### 7.2 知识生命周期

知识经历草稿、业务审核、必要的相关部门审查、发布、生效、变更与下架。发布者和审核者按银行制度分工，生产知识留有版本与责任人。

知识记录需包含业务域、个人或企业类型、适用渠道、适用地区与产品、来源、生效与失效时间、审核状态和版本。检索时先筛选适用范围，再匹配问题。

涉及客户决策的产品说明应准确、及时并完整呈现重要信息；存在相互冲突、已到期或未经审核资料时，不自行选择最有利于营销的说法。[银行保险机构消费者权益保护管理办法第十条及第二十一至二十三条](https://fgw.sh.gov.cn/ys-hqjrfw-1.3.3.2/20240821/70e2f039318d4d7a96c7b81b87e1fb31.html)提供信息披露与防止误导的监管背景，知识发布流程属于本版产品设计。

### 7.3 回答生成

1. 识别服务对象、业务意图、是否紧急、是否需要身份或数据。
2. 检索适用的银行审核知识或请求已授权工具。
3. 答案使用检索与工具结果支持的事实，不编造金额、成功结果和处理承诺。
4. 输出前检查关键业务字段、敏感内容、产品类型及必要风险提示。
5. 图文与口播使用同一已通过检查的答案版本；动作不得强化错误的收益或成功暗示。
6. 保留答案的知识版本或工具关联信息，供授权人员追踪。

公开答案可做自然语言解释；重要风险内容采用银行批准的表达。实时金额和交易状态使用确定性模板或安全组件，避免自由生成改变数值、单位、日期或状态。

### 7.4 拒答与澄清

无可靠依据、接口不可用、问题涉及未开放业务、客户对象不清或权限不足时，明确当前不能确认的内容，提出必要的澄清问题或提供正式渠道。不得以未经校准的置信度分数作为放行金额、账户或交易判断的唯一依据。

贷款拒绝原因、账户限制原因及风控细节按银行允许披露的范围回答；不得推测客户征信、泄露控制规则或提供绕过身份与风控的方法。

### 7.5 产品信息与适当性

理财及相关投资型产品的信息说明区分存款与其他产品，披露获准展示的风险、费用、期限和流动性信息。客服不替用户填写风险测评，不教用户选择答案以获得特定风险等级，不宣称本金或收益保证。

《金融机构产品适当性管理办法》自 2026-02-01 施行，规定范围内的投资型产品与保险产品有相应适当性要求，证券基金期货产品适用规则需进一步区分。[商务部官方法规文本第三条及第十三条](https://policy.mofcom.gov.cn/claw/clawContent.shtml?id=103294)支持该边界。本期仅提供审核信息与正式办理入口，个体推荐和销售能力需另行评审。

贷款说明采用银行批准的年化利率、费用与条件披露；示例测算须标注假设与非审批结果。贷款产品的关键披露要求可参考[银行保险机构消费者权益保护管理办法第二十二条](https://fgw.sh.gov.cn/ys-hqjrfw-1.3.3.2/20240821/70e2f039318d4d7a96c7b81b87e1fb31.html)。本文件不填写未经目标银行核定的真实利率或额度，首轮演示不提供此类数值，也不判定贷款资格；后续正式服务只展示允许披露的生效资料或授权查询结果。

### 7.6 知识准备、审核与发布

| 步骤 | 责任角色 | 输入与产物 | 关闭条件 |
| --- | --- | --- | --- |
| 准备 | 银行业务负责人；L0 为产品验证人员 | 正式公开材料及允许用途；演示资料单独标识 | 每条记录有出处、客户类型、主题与版本，无认证要素或私有明细 |
| 审核 | 对应业务审核人及必要的消保/合规岗位 | 核对适用条件、重要限制、风险说明与展示人群 | 审核结论可追踪；演示资料不得变成银行已审核状态 |
| 发布 | 有发布权限的知识维护人员 | 生效/失效时间、适用渠道/地区/产品、审核版本 | 发布内容与被审核内容一致，未生效或失效材料不检索 |
| 更新 | 业务负责人发起、审核及发布角色承接 | 变更说明、新版本、关联答案与入口影响 | 新旧版本切换可核对，不把“新版本待审”当成已生效 |
| 下架与冲突处理 | 银行授权维护岗位 | 停用、冲突或错误记录，待处理责任 | 新回答和待播内容不继续使用失效知识；由责任岗位处理冲突后再发布 |

角色是职责划分，具体人员和银行制度待确定。知识维护优先复用银行现有平台；是否另建管理界面由范围评审决定，首轮仅需受控本地资料，不默认新建完整知识后台。

### 7.7 回答与来源呈现

回答至少区分结论或说明、重要条件/风险、来源和下一步。对客来源显示资料名称、银行/发布主体、使用版本或更新时间、适用对象；来源链接仅使用银行批准的公开地址，内部文档不得直接外链。

L0 显示主题、演示版本及“未获银行审核”，可在受控详情中查看生效范围。多来源组合时分别关联事实与来源；资料冲突时不拼接为确定结论。缺少来源或来源过期不能仅靠模型自报高置信度放行。

### 7.8 模型职责与改写边界

| 内容 | 允许行为 | 禁止行为 |
| --- | --- | --- |
| 意图及知识选择 | 在适用候选知识中选择，不能匹配时返回无依据 | 生成候选之外的权威资料、改变身份或自行增加工具权限 |
| 审核解释 | 仅在明确批准可改写的范围内简化表达，保留所有条件与限制 | 改变产品属性、删去重要限制或把可能性改成承诺 |
| 必须固定的提示 | 使用银行审定的风险及紧急表述 | 自由改写导致风险含义变化 |
| 利率、金额、日期、状态、关键资格 | 取自生效知识或授权接口，以受控模板展示 | 补造、推算业务状态、变更单位或币种 |
| 模拟测算 | 首轮不交付，后续另评审确定性计算与假设 | 把测算说成授信、收益或办理结果 |

当前规则模式不调用模型。现有模型适配器仅预留知识编号选择，未开放自然语言金融改写。未来放开改写前需明确数据流和相应真实样例验收；不因模型替换而自动扩大其权限。

调用必须有结构校验、超时、有限重试及初始化失败兜底。重试次数和错误类别可追踪，日志不含认证要素或完整用户原文；模型未取得有效结果时给出降级状态，不将规则结果包装成真实模型输出。

### 7.9 产品信息发布范围

公开咨询按资料适用人群和内容用途筛选。金融概念教育、公开产品说明、受限产品材料和个体化推荐分别管理，资料已审核不代表允许向所有访客展示。

涉及私募产品时，首轮不做具体产品推介；银行试点应由相关岗位确认访问对象、展示内容、入口及可披露范围。不得向不特定对象宣传推介私募产品，依据为[金融机构产品适当性管理办法第三十条](https://policy.mofcom.gov.cn/claw/clawContent.shtml?id=103294)。公开咨询不能充当销售准入或适当性流程。

### 7.10 财富服务内容分型（CF08）

| 类型 | 允许范围 | 开通要求 |
| --- | --- | --- |
| 金融概念与投资者教育 | 解释概念、风险和一般流程，不代客户作投资决定 | L2 有效且适合公开人群的审核内容 |
| 公开产品条款解释 | 说明已允许披露的条款、费用、风险、适用人群及正式入口 | 按 7.5、7.9 审查可见范围；已审核不等于可向所有人展示 |
| 本人持仓只读展示 | 与教育和条款解释分开 | 本版未新增持仓查询包；需另评接口、权限、字段与私有展示 |
| 个体投资推荐、持仓诊断与资产配置 | 暂不纳入 | 不因客户自报资产、偏好或企业闲置资金而开启 |

“我有 10 万元买什么”“企业闲置资金怎么拿最高收益”等请求不得自动生成个体配置、收益排名或购买建议；可以解释审核后的产品类别和风险，提供正式咨询路径。历史收益不得改写为未来承诺，适当性流程仍由银行正式渠道承担。L0 不扩展六类演示知识，也不填充真实产品、费率或收益样例。

## 8 查询工具与办理入口

### 8.1 工具调用规则

每个查询工具需配置适用客户类型、认证要求、账户范围、允许字段、数据来源、超时与更新口径。工具执行由服务端白名单与权限校验控制，不因模型输出了工具名或参数而直接访问银行系统。

账户与企业标识由可信上下文或受控选择器获取。用户消息中出现的账户号、企业名、查询指令或外部链接不作为访问授权。

本期查询工具只读。支付、授权变更、审批、冻结等写入操作不登记为本期聊天可调用工具。投诉或人工交接工单可在用户明确提交意图及银行渠道规则下执行，独立于资金交易权限。

### 8.2 结果展示

| 信息 | 展示方式 | 口播方式 |
| --- | --- | --- |
| 公开产品说明 | 审核文本与来源提示 | 可以播报审核摘要 |
| 账户或卡片标识 | 按银行规则脱敏的受控卡片 | 不播报完整标识 |
| 余额、还款金额和企业资金信息 | 身份有效时在安全卡片内按权限展示，默认遮挡策略待银行确认 | 一期不播报私有金额，提示用户查看安全卡片 |
| 私有交易和业务状态 | 显示银行原始状态对应的审核解释、查询时间与单位 | 一期不播报敏感细节，可播报中性引导 |
| 回单、账单与对账单 | 银行正式受控页面查看或下载 | 不将原始文档转成自由生成口播 |

私有原始数据默认不发送给数字人视频渲染或第三方 TTS。实时金额和明细由银行受控组件读取与展示；供应商接触范围需完成数据流评审。

### 8.3 数据准确性

结果需包含数据时间、币种、单位和状态定义。信用卡账单金额、已还金额、最低还款额、剩余应还额等字段按业务系统定义分别展示，不进行未经确认的加减推算。

企业结算的“已提交”“已受理”“处理中”“成功”“失败”和“结果未知”按银行接口定义展示，不能把已受理解释成收款人已到账。接口超时不代表交易失败，不应引导客户立刻重复提交支付。

### 8.4 办理入口

办理按钮清楚表示“前往办理”“查看账单”或“查询进度”。链接目标采用银行配置的允许列表，跨页前说明将进入正式业务流程。

转账、还款、挂失、账户变更、融资申请和企业审批在正式业务渠道中执行。返回客服时默认只知道用户已返回；只有授权接口或可信回调返回结果，才能展示相应办理状态。客服不得因页面打开、按钮点击或客户说“好了”而宣布办理成功。

### 8.5 统一服务卡片（CF03）

| 卡片类型 | 必要内容 | 动作与状态边界 |
| --- | --- | --- |
| 公开说明卡 | 标题、个人/企业适用对象、说明、知识来源/版本/有效时间、演示或正式标记 | 查看详情或继续问；不承载客户账户结果 |
| 材料/步骤卡 | 审核材料或流程步骤、适用条件、来源与更新信息 | 展开/下一步/返回；展开和看完不代表已办完 |
| 官方入口卡 | 业务名称、银行正式入口、适用渠道、是否需认证、当前可用状态 | “前往官方办理”；无允许地址不生成链接，L0 只显示未接入说明 |
| 授权结果卡 | 查询对象、授权范围、银行原始业务状态、数据时间及允许展示字段 | L3 按包只读；认证失效、切换或撤销时即时清除失效展示 |

共同字段包括卡片/能力标识、类型、所属消息与对象、来源/版本、能力状态、允许动作和展示有效性。来源更新时间、查询数据时间与页面渲染时间分别标注，不能用当前页面时间制造数据新鲜度。

能力状态至少区分“演示可用、正式可用、需认证、权限不足、未接入、暂不可用”；业务状态另按银行返回表示，不从卡片外观推断成功。L0 只启用公开演示卡，不出现虚构银行卡、账单或余额。步骤超出演示资料时明确不能确认。

按钮绑定受控能力编号及允许动作。模型最多提出候选，后端重新检查开关、来源、对象、权限及正式地址配置；不直接执行模型生成的 URL 或业务指令。点击时重新校验，不能仅依赖卡片生成时的状态。过期卡可保留允许的历史说明，但须标记失效并停止动作。

### 8.6 返回客服后的任务续接（CF04）

导航记录只表达客服可证实的事件：“入口已展示”“已发起前往”“已返回，结果待确认”；无法检测跳转/返回时不假称已经发生。业务办理结果独立保存，来源必须为相应银行接口或经过核定的可信回执。

只有当前可信身份、企业/账户范围、业务关联标识及已开通查询包均满足时，才提供“查询办理进度”。L3 只查询第 4.3 节已允许的状态，不自动扩展至任意转账、挂失、开户或投资交易状态。没有接口则显示“当前无法确认，请在官方渠道核对”。

用户说“办好了”、关闭页面、刷新或再次返回均不能转成银行成功状态。旧任务、其他企业或他人回调不得进入当前卡片；状态超时不提示重复支付或重新提交。L0 不创建真实办理任务。

## 9 分流与核心服务流程

### 9.1 服务入口与数字人引导

进入客服后提供个人业务、企业业务、人工服务与账户安全入口。客户可直接提问，系统只在必要时澄清服务类型。登录渠道可以预选业务类型，但客户进入企业上下文仍需校验权限。

常规问题命中可展示数字人的业务知识、入口开关开启且展示资源可用时，可提供数字人引导卡片。每个当前咨询会话仅主动展示一次，客户仍可手动启用数字人。

客户选择文字服务时继续获得相同业务能力。紧急问题、身份校验和人工请求不依赖数字人加载成功，也不受一次性卡片展示限制。

### 9.2 公开业务咨询

1. 客户以文字或语音提出问题。
2. 识别个人或企业业务与意图，必要时澄清。
3. 检索审核知识，检查生效状态与渠道适用性。
4. 输出解释、重要条件、风险信息及正式办理入口。
5. 数字人可播报同一答案的摘要，文字保留完整内容。
6. 无依据或复杂问题提供相应人工队列。

### 9.3 个人授权查询

1. 客户请求本人账单、余额或贷款状态。
2. 检查认证状态、查询包是否开通及所需数据处理流程。
3. 如需认证，进入银行正式页面完成并返回。
4. 服务端校验本人归属与字段权限，调用只读接口。
5. 输出带查询时间的安全卡片，口播只作中性引导。
6. 超时、无数据或失效时说明当前不能确认结果，提供重试或正式查询入口。

### 9.4 企业授权查询

1. 客户进入企业服务，选择被授权企业。
2. 验证企业关系、操作人、岗位和账户范围。
3. 选择查询业务与授权账户，校验对应查询包。
4. 调用银行只读接口，展示当前企业与时间信息。
5. 无权限时停止查询，并引导企业授权管理或对公客服。
6. 切换企业时中止旧请求与播放，不恢复原企业数据到新上下文。

### 9.5 业务办理引导

1. 判断客户需要的是咨询、查询还是实际操作。
2. 解释办理条件和所需官方流程。
3. 展示目标银行受控办理入口。
4. 客户在正式渠道中完成认证、确认、风控和必要审批。
5. 返回客服后通过已开通的授权查询获取状态，未取得结果时不作成功判断。

### 9.6 企业融资咨询

企业融资咨询先确认所询问的产品与公开条件，提供材料类别和银行承接路径。企业申请状态通过经授权的接口查询；审批结论、授信额度、担保要求和放款时间只按权威结果解释，无法确认时转接对公业务人员。

对外沟通不以“满足材料即获批”“有流水就一定有额度”等表述制造承诺。对具体拒绝原因或内部授信模型的解释遵循银行可披露范围。

### 9.7 多轮澄清与上下文切换

以下规则沿用 V1.2。本机有限样例已有实现与验证，银行语义覆盖仍待对应包实测。用户明确给出服务对象且没有冲突时直接使用相应公开知识；只有消除业务歧义所必需的信息才询问，不要求客户提供完整账户号或认证要素。

| 示例输入或事件 | 处理规则 | 核对点 |
| --- | --- | --- |
| 未选服务类型，询问“开户需要什么材料” | 询问个人或企业；银行渠道可信预选可用于公开咨询 | 不把个人材料套用于企业 |
| 个人语境中明确询问“企业开户材料” | 提示切换企业公开咨询，客户确认后切换或明确本条是企业公开答复 | 不继承个人认证为企业查询授权；历史展示保持所属语境 |
| “个人贷款和企业融资都要哪些材料” | 拆分并标记两个公开问题，逐项处理，不能用一个对象套全部答案 | 私有信息仍分别要求授权；界面不混合身份或企业数据 |
| “那需要什么”且前一问题对象不明确 | 询问指代对象，不猜测当前企业或账户 | 澄清与业务答案可区分 |
| 连续追问同一主题 | 沿用仍有效的公开咨询主题，重新检查知识版本 | 不沿用失效知识或旧权限 |
| 中途切换个人/企业或企业 A/B | 终止旧请求展示资格，保存允许的历史并建立独立新语境 | 迟到答案不进入新语境；私有内容立即清除 |
| 用户取消或拒绝澄清 | 保留已确认的公开说明，提供正式路径，不反复逼问敏感字段 | 不因未回答而授予查询权限 |

澄清持续无进展时应说明无法确认并给出正式路径或当前未接入状态。L0 已支持有限规则内的对象识别、混合公开问题与主题追问；不能据此宣称通用自然语言理解、任意多意图或银行认证已通过。

### 9.8 对话任务导航（CF02）

服务先区分公开咨询、授权查询、正式办理指引、人工/投诉和紧急求助，优先级沿用第 10、11、13 节。公开问答可以形成“问题—有效说明/步骤—相关问题或正式入口”的有限导航；选择建议问题和手动输入使用同一知识、对象及权限检查。

用户可返回上一步、取消当前普通导航或切换主题。取消后停止该导航的追问和待展示步骤，保留仍有效的公开历史；切换个人/企业后终止旧导航展示资格。用户取消普通任务不等于关闭有效紧急提示，紧急提示仍按第 13.4 节独立处理。

同一主题后续问题只从第 5.5 节受控配置选择，不从开户咨询擅自转向贷款营销。无依据、对象不清或步骤缺失时澄清/说明限制，不能编造办理步骤。L0 导航仅覆盖现有六类演示主题，导航阶段和资料来源需要可恢复；不把有限流程称作已验证的自主办理智能体。

## 10 账户安全与紧急服务

### 10.1 紧急场景

| 场景 | 首次响应 | 后续处理 |
| --- | --- | --- |
| 银行卡遗失或疑似被盗用 | 立即显示官方挂失及紧急人工入口 | 实际挂失在银行正式渠道执行，客服不宣布已挂失 |
| 疑似盗刷、异常扣款或未授权转账 | 提供银行紧急联系及相应争议入口 | 交接安全或银行卡专席，不对责任和退款作结论 |
| 泄露验证码、密码或被要求转款 | 提醒停止披露认证要素，使用官方安全路径 | 不要求用户把验证码发给客服核验 |
| 企业凭证或网银账户疑似被冒用 | 提供企业网银安全处理及对公人工路径 | 不代替企业修改权限、冻结账户或重置凭证 |
| 客户怀疑诈骗 | 显示经银行审核的简洁风险提示与官方求助方式 | 不以继续数字人讲解延迟实际求助 |

电话号码、跳转入口、服务时段和应急提示必须由目标银行配置。紧急公开提示不要求客户先通过私有查询认证；账户变更操作仍需要正式认证。

### 10.2 紧急消息处理

识别到紧急意图或接收到可信安全事件后，中断欢迎语、普通咨询口播和推广内容，立即展示安全操作路径。数字人不可用时仍展示相同文字和人工入口。

安全提示可由用户暂停播放或关闭音频，但关键文字和处理入口保持可见。紧急服务不因满意度评价、营销提示或排队欢迎语而被覆盖。

### 10.3 处理状态

“已经提供挂失入口”“已提交安全工单”“已连接人工”和“银行卡已挂失”分别记录。只有银行业务接口明确返回挂失状态，且查询权限有效时，才能展示实际账户结果。

## 11 人工承接与投诉

### 11.1 转人工条件

- 客户主动要求人工。
- 账户安全、疑似诈骗、复杂异常和需要专席处理的场景。
- 知识缺失、业务规则冲突或无法获得权威数据。
- 需要银行人员解释、权限处理、贷款沟通或企业业务服务。
- 客户提出投诉、扣费异议、权益争议或持续不认可答复。

系统可以提出人工建议，但不能以客户未接受数字人服务或未完成评价为由阻止转人工。

### 11.2 队列与交接

| 类别 | 建议队列 | 交接内容 |
| --- | --- | --- |
| 个人账户与银行卡 | 个人客服或银行卡专席 | 业务意图、认证状态、脱敏对象、已给出的处理路径 |
| 信用卡或个人贷款 | 相应业务专席 | 业务类别、授权查询摘要、问题描述 |
| 企业账户与结算 | 对公客服 | 当前企业、操作者授权状态、账户范围和结算问题摘要 |
| 企业融资 | 对公融资服务或客户经理队列 | 已知申请关联信息、材料或进度问题 |
| 紧急安全 | 银行设置的紧急安全队列 | 紧急类别及最少必要信息，不含密码或验证码 |
| 投诉与争议 | 投诉或争议处理队列 | 客户诉求、事件摘要、工单引用和已有答复 |

队列名称与服务时间待银行确认。转接失败或非服务时段时，给出官方电话、正式工单或网点路径，不编造预计等待时间。只有队列服务返回有效等待信息才可展示。

人工接管成功后，自动业务回答停止。交接数据在银行受控坐席系统内按权限传递，不将完整个人或企业数据发送给任意坐席。

### 11.3 投诉与工单

客户明确提出投诉时，提供正式受理入口或经银行批准的工单流程。提交前让客户确认诉求与必要联系信息；提交后以工单系统回执为依据显示受理编号、状态和银行规定的反馈渠道。

工具超时但受理结果未知时先核对请求状态，防止重复创建工单。未获得回执不能写“投诉已受理”，也不能把一次客服满意度评价替代投诉受理。

投诉渠道与信息披露方面的背景依据包括[银行保险机构消费者权益保护管理办法第十五条](https://fgw.sh.gov.cn/ys-hqjrfw-1.3.3.2/20240821/70e2f039318d4d7a96c7b81b87e1fb31.html)。企业客户适用的争议流程、个人金融消费投诉规则与具体处理时限需由银行分别核定，本版不统一编造办结天数。

### 11.4 人工、投诉与恢复状态

| 当前状态 | 进入/退出条件 | 自动客服行为与证据 |
| --- | --- | --- |
| 人工请求待发起 | 用户主动请求或符合转接规则；必要交接数据已最小化 | 普通业务生成暂停，显示正在请求；不能显示已连接 |
| 排队 | 真实队列返回有效受理或排队状态 | 仅展示真实队列信息，允许取消；紧急路径持续可达 |
| 人工接管 | 坐席服务返回接管成功 | 自动业务回答停止，按坐席权限交接 |
| 取消/失败/非服务时段 | 用户取消或可信队列事件表明失败 | 显示真实原因及可用替代路径；需要用户选择才恢复普通智能咨询 |
| 人工结束 | 可信坐席事件表明结束 | 不自动复播旧答案；询问继续智能咨询或结束会话 |
| 投诉待确认 | 客户表达提交意图且必要字段就绪 | 展示诉求摘要和提交确认，不把差评当投诉 |
| 已受理/结果未知 | 真实回执或提交结果暂无法核定 | 有回执才显示受理，未知时核对状态，不重复提交 |

状态和用户确认点需持久化。取消排队或关闭聊天不能自动撤销已受理投诉；撤销如需支持，使用正式流程另行确认。L0 仅显示未接入状态，不生成上述真实队列或工单事件。

### 11.5 可核对的人工交接摘要（CF06）

真实人工渠道开通后，交接摘要包括当前咨询对象、用户当前问题、已给出的公开说明、已尝试步骤和尚未解决事项。分别标注“用户陈述”“审核知识”“银行接口事实”及必要来源，用户可查看并纠正自己的陈述；不能通过编辑把用户陈述变成银行事实。

摘要优先使用公开信息。私有信息仅在业务必需、用户确认和双方岗位/数据权限允许时传递受控引用，不默认复制完整历史、金额明细或凭证。企业摘要绑定当前企业的受控上下文，切换后重新确认，不混入另一企业内容。

用户请求人工即进入承接流程，摘要可查看/纠正但不作为排队前必须填写的表单。仅在真实确认后发送允许摘要；拒绝摘要分享仍提供人工路径，不阻断紧急求助。摘要准备完成不等于已连接坐席，接管状态以坐席系统为准。

L0 继续仅提示真实未接入状态，本次不生成或发送人工交接资料。

## 12 页面与数字人交互

### 12.1 页面结构

| 区域 | 展示内容 |
| --- | --- |
| 服务身份区 | 个人或企业类型、当前企业的适当标识、认证状态与切换入口 |
| 对话区 | 客户消息、审核答案、来源说明、风险内容与业务路径 |
| 受控查询区 | 经授权的账户、账单和企业业务安全卡片 |
| 数字人区域 | 银行批准形象、口播与动作、AI 身份提示、暂停或关闭入口 |
| 输入区 | 文字输入、语音切换、语音取消与发送 |
| 常驻服务入口 | 人工、安全帮助、服务类型切换与评价 |

数字人区域可收起，不遮挡账单、关键风险和人工入口。个人与企业上下文切换后，页面清楚呈现当前服务对象。

### 12.2 形象与欢迎语

银行形象、名称、服饰、音色和数量由品牌与业务评审确定，不继承原文蓝灵四形象作为银行既定配置。形象应说明其为智能客服，避免暗示真人客户经理正在进行实时判断。

拟采用的欢迎语示例为“您好，我是金融智能客服。您可以咨询个人或企业银行业务，需要办理时我会引导您进入官方渠道。”实际银行称谓及语言由银行审定。

从 FAQ 进入时，优先承接当前问题；欢迎语简短且不重复播放已展示的业务答案。紧急服务跳过欢迎语。返回页面使用中性引导，不播报私有账户摘要。

### 12.3 语音与敏感输入

语音为可选方式。麦克风权限拒绝、识别失败或环境不合适时继续使用文字。发送前允许客户检查识别文本，关键业务对象通过受控选择器确认，不凭识别出的卡号直接查询。

输入区提示客户勿发送密码、验证码等认证要素。已进入聊天的疑似凭证进行屏蔽，避免继续进入模型上下文、记录、回放和后续工具；原始语音可能经过识别服务的路径，需要在供应商与数据流审查中处理，不能仅凭转写脱敏宣称原始音频从未被处理。

### 12.4 适老与无障碍

提供字体调整、清晰对比度、完整文本、键盘和读屏可操作的服务入口。语速和播放可调，关键金额与风险不依赖动作、颜色或音频单独表达。

适老与无障碍建设有相关监管背景，见[银行保险机构消费者权益保护管理办法第三十八及三十九条](https://fgw.sh.gov.cn/ys-hqjrfw-1.3.3.2/20240821/70e2f039318d4d7a96c7b81b87e1fb31.html)。具体控件与终端验收方案为本版产品设计。

### 12.5 AI 内容标识

在交互界面清楚标识智能客服和数字人身份。涉及生成合成音视频、下载与导出时，按适用规则落实标识，不以普通品牌名称替代相关标识。

[人工智能生成合成内容标识办法第三至五条及第十四条](https://www.cac.gov.cn/2025-03/14/c_1743654684782215.htm)区分显式、隐式标识，并自 2025-09-01 施行。具体场景适用性、文件元数据和音视频链路由银行与技术供应商评审，界面提示属于本版设计的一部分。

### 12.6 口播与动作事件配置

银行口播配置关联业务场景、审核文本、允许动作、客户类型、有效版本和播放优先级。普通答案与特殊事件均应使用当前生效配置；缺少口播配置时只展示合格文字，不临时生成未经审核的金融承诺。

| 业务事件 | 播放与展示行为 | 优先级 |
| --- | --- | --- |
| 首次进入 | 简短说明智能客服身份，承接当前问题 | S4 |
| 普通业务答案 | 播放已通过检查的公开知识摘要，文字保留完整内容 | S3 |
| 打开安全查询卡片 | 中性提示查看受控卡片，不播报私有金额或明细 | S2 |
| 前往正式办理渠道 | 说明将进入银行页面，不描述业务已完成 | S2 |
| 人工转接或排队 | 按真实队列状态提示，不编造时间 | S2 |
| 返回客服 | 中性欢迎，不恢复旧账户或企业私有口播 | S2 |
| 紧急账户安全 | 提供审核的安全提示与官方路径 | S1 |
| 认证或授权失效 | 先停止相关展示与播放，再提示重新认证或权限处理 | S0 |
| 评价邀请 | 不覆盖紧急或业务处理内容 | S4 |

动作保持与文本语义一致，办理入口、融资或产品信息不能使用暗示已批准、保证获利或交易成功的庆祝动作。银行事件标识和协议映射需统一评审，V1.0 的 0001 至 0005 仅为历史指令，不能直接当作银行系统既定编码。

### 12.7 敏感输入与正常咨询的区分

| 输入类别 | 示例，均为虚构测试用途 | 处理要求 |
| --- | --- | --- |
| 公开流程咨询 | “忘记密码怎么办”“验证码收不到怎么办” | 可提供已审核的正式重置/处理路径，不要求发送凭证；不能仅因含“密码”二字就把正常问题当凭证 |
| 实际凭证披露 | “验证码是111111”“我的交易密码是〔虚构占位〕” | 保存与模型调用前屏蔽；页面、音频、历史与日志不回显原值 |
| 正常期限、年份或金额讨论 | “贷款期限36个月”“2026年网点安排在哪里查” | 数字本身不构成认证凭证；依知识和隐私场景处理，不仅凭数字长度判断 |
| 账户、联系方式或其他个人信息 | 完整卡号、手机号、联系邮箱等测试占位 | 无必要时不收集；需业务对象时用受控选择器，普通聊天不能据此认证或扩大权限 |
| 凭证披露同时有紧急风险 | “被盗刷，并把验证码发给对方了” | 屏蔽原值，同时保留最少必要的紧急意图用于确定性路由，不让屏蔽阻断公开求助提示 |
| 原始语音包含敏感要素 | 只使用合成测试音频 | 分别核对识别服务接触范围、转写屏蔽与留存，不以文字脱敏替代音频数据流审查 |

上述样例均要求用虚构内容验收。V1.2 修订已验证有限的正常密码流程、年份/金额咨询与虚构凭证对照样例，见 LV15 及修订证据。该结果不代表生产资料覆盖、真实模型输入或音视频传播链路已验收；对应正式能力仍需补验。

### 12.8 AI 标识检查矩阵

标识适用范围由银行和供应商结合[人工智能生成合成内容标识办法](https://www.cac.gov.cn/2025-03/14/c_1743654684782215.htm)核定；下表用于明确责任与可核对产物，不把品牌标志当作合成标识。

| 场景 | 待核定/验收内容 | 责任角色与证据 |
| --- | --- | --- |
| 规则演示文字 | 明确规则演示、资料未获银行审核和真实模型待验，不宣称模型生成 | 产品/前端；页面截图与模式记录 |
| 模型生成文字 | 对适用生成内容和交互界面落实清晰可感知的提示 | 产品、合规、前端；页面、读屏及内容样例 |
| 生成语音 | 适用的显式提示、播放路径及可感知性 | 语音供应商、产品、合规；录音/播放与提示检查 |
| 数字人视频 | AI/数字人身份与适用的显式标识，暂停或降级后文字仍可见 | 数字人供应商、前端、合规；视频和降级页面 |
| 下载/导出生成文件 | 按适用规则核对显式与隐式标识、文件元数据及转码后保留情况 | 生成/导出链路、供应商、合规；文件样例与检查记录 |

无导出能力时相关项记为不适用，不能据此推断未来导出已通过。

### 12.9 分步讲解与语音任务确认（CF09）

数字人开通后提供“简短回答”和“分步讲解”，每一步关联同版文字与服务卡片。用户主动选择下一步、重复、跳过或退出；停止数字人后仍能阅读完整文字。讲解完成只表示内容播放完，不表示业务完成。

语音输入沿用现有识别、转写核对和取消规则。对象、账户或业务意图有歧义时先通过受控选择澄清；转写本身不授予权限。用户取消的录音/转写不得自动提交咨询；对话仍不执行第 4.4 节业务变更。语音与文字得到同一权限范围、来源和服务状态，不因模态不同扩大工具能力。

紧急提示、权限失效及人工接管立即停止不再有效的普通讲解。真实坐席接管后明确显示当前服务者，不能仅因数字人换表情就标记人工已连接。人工结束/断开后按第 11.4 节恢复，不自动重播旧私有内容。待播知识被下架时停止对应讲解。

L4 的原始音频、转写、TTS、数字人资源分别完成数据流与标识评审；首轮保持关闭，不因本项需求提前采购供应商或采集音频。

## 13 应答同步与消息打断

### 13.1 图文与口播同步

普通审核答案使用统一应答标识关联图文、口播、动作、知识版本和播放开始通知。数字人准备好后可联动展示；收到图文后等待口播开始通知的建议上限为 2 秒，超时直接展示图文。

2 秒从图文到达前端开始计时，是沿用 V1.0 的普通展示建议，不是银行接口响应或身份校验承诺。紧急提示、权限失效提示和安全卡片不等待数字人口播；只有完成认证与数据检查的卡片才能显示，超时不能绕过这些条件。

迟到播放通知不重复插入图文。通知与当前身份或企业上下文不匹配时直接丢弃，不恢复旧数据或旧口播。

### 13.2 播放优先级

本版新增安全事件优先级，调整 V1.0 中全部事件可相互打断的通用规则。

| 优先级 | 类型 | 处理规则 |
| --- | --- | --- |
| S0 | 认证失效、上下文切换、企业授权撤销等可信状态事件 | 立即中止相关私有内容与播放，清除展示；不排队等待 |
| S1 | 账户安全、疑似诈骗及紧急处理提示 | 打断欢迎语、普通回答与一般事件，保持处理入口可见 |
| S2 | 人工接管、正式渠道跳转、返回与流程提示 | 可打断普通回答；不覆盖有效的 S1 提示 |
| S3 | 普通知识答案 | 新咨询可打断旧咨询；播放前确认当前问题与上下文仍有效 |
| S4 | 欢迎语与评价邀请 | 最低优先级，不影响业务与紧急处理 |

同级事件按有效性、最新业务上下文和确定的状态机处理，不简单让所有后到消息覆盖前一条。可信状态变化由后台与前端安全逻辑处理，不交给语言模型决定。

### 13.3 队列与停止

普通咨询连续到达时，等待播报队列只保留当前需要的最新答案，被新意图替代的旧回答不恢复播报。完整文字历史可保留在允许的会话范围内。

人工接管、退出、切换上下文或用户停止播放后，不自动恢复被中止的旧回答。数字人衔接流失败时保留文字服务，并阻止音视频错配。

### 13.4 紧急态的持续与解除

进入紧急态后，关键公开文字和正式求助路径持续可见，直到客户明确选择关闭该提示或可信业务事件按银行批准规则表明本次提示可结束。普通回答、满意度评价或经过一段时间不能单独作为解除依据。

认证失效与企业切换必须即时清除对应私有结果；同时保留仍适用的公开求助内容。企业专属或已不适用的旧路径不得带入新上下文，应改为有效的公开安全路径。

用户关闭提示只表示不继续显示或播放，不代表风险已消除、账户已冻结或争议已处理。人工结束、重新进入或继续咨询时不复播旧敏感答案，必要时重新提示仍未解决的风险。

L0 已验证公开紧急提示持续、主动关闭、切换/刷新及实际进程重启恢复，见 LV16 及修订证据。银行可信结束事件、真实人工接管和音视频复杂打断仍待对应包验收，不能由本机样例替代。

## 14 会话与房间生命周期

### 14.1 生命周期区分

| 对象 | 作用 | 失效影响 |
| --- | --- | --- |
| 客服会话 | 记录当前咨询与服务切换 | 会话结束后按规则新建，历史受权限控制 |
| 银行认证会话 | 表示用户有效身份 | 失效后停止私有查询与展示 |
| 企业授权上下文 | 表示当前企业及账户权限 | 变化后旧工具结果和私有历史不可继续展示 |
| 数字人房间 | 音视频展示资源 | 丢失或销毁后回退文字，可按条件重新创建 |
| 查询缓存 | 减少重复读取，受时间与权限约束 | 不能跨身份、跨企业复用；过期结果不可伪装为实时值 |

数字人房间仍存在不代表认证仍有效。房间与客服会话可复用时，也必须重新验证当前身份、企业和权限后才显示客户数据。

### 14.2 保留与回收

V1.0 提出的退出后保留房间 20 分钟，仅作为资源回收候选参数。本版要求保留时间可配置，并由银行安全与容量评审确定。认证失效的清除和阻断即时生效，不等待房间回收。

切换客户或企业时必须切断旧内容引用；新上下文是否使用新房间由技术选型决定，但不能复用旧音频队列、鉴权引用或查询结果。房间回收需防止销毁和重新加入的竞争，退出后不执行无人接收的私有播报。

### 14.3 刷新与返回

刷新、H5 前进后退、App 返回和重新进入时，先验证当前上下文与认证，再恢复允许的公开会话和数字人。历史安全卡片以重新校验后的数据展示，不能仅依赖浏览器缓存恢复。

正式业务办理后返回页面不默认认为业务成功。房间已销毁时可重新建立，身份有效性仍由银行身份服务判断。

### 14.4 跨渠道续接卡片（CF07，可选扩展）

目标是用户在电话、手机银行或其他已批准渠道转换时，继续一个尚未结束的咨询任务。源渠道内容先按 CF06 形成最少摘要；在完成渠道、可信身份映射、授权、有效期和发送方式评审前，保持未开通。浏览器本机会话凭证不作为跨渠道银行身份。

用户主动选择继续，接收渠道重新核对同一可信身份及当前企业/账户权限；私有部分还须满足 L3。卡片不通过公开 URL、二维码明文或消息预览携带私有历史和凭证。续接标识有有效期和受控使用次数，失效、撤销、身份不符或重复使用时拒绝读取；具体期限在开通前冻结。

只恢复允许的摘要、任务引用和当前可验证状态，不复制所有聊天和旧认证，不使源渠道历史的权限延长。纯公开 L2 续接只恢复允许摘要与导航状态；只有相关 L3 查询包已开通、关联标识有效且当前身份权限满足时，接收方才按第 8.6 节重新查询银行状态。无查询能力时保留结果未知并提供正式核对路径，不能把旧卡片结果当实时值。目标渠道不可用或续接失败时保留已允许的当前服务，明确失败且不反复外发。

该扩展不在 L0，也不作为 L2 基础试点的必需条件；外部消息发送、电话内容留存和私有数据流均需独立确认。

## 15 异常与降级

| 异常 | 用户响应 | 业务约束 |
| --- | --- | --- |
| 数字人创建或加入失败 | 保留文字服务、重试和人工入口 | 不影响公开咨询或紧急处理 |
| 数字人容量不足 | 提示暂时无法播放，继续文字或人工 | 不阻断银行服务入口 |
| 图文与口播同步超时 | 普通图文直接展示 | 身份和数据检查仍有效，迟到通知不重复 |
| 音视频或模型异常 | 停止异常播放，展示审核文字或失败提示 | 不播放无法确认的业务内容 |
| 未找到适用知识 | 说明暂无可确认信息，澄清或转人工 | 不临时生成费率、条件或承诺 |
| 知识冲突或过期 | 停用相关自动答案，转正式信息源或人工 | 运营记录待修订项 |
| 银行接口超时 | 显示当前未取得结果，可重试或前往正式查询 | 不用历史值或模拟值冒充实时结果 |
| 认证过期 | 隐藏私有结果，重新认证或继续公开咨询 | 不自动延长认证，不以 roomid 替代凭证 |
| 企业权限不足或被撤销 | 停止查询，给出权限处理或对公服务路径 | 不使用模型或缓存绕过授权 |
| 查询返回对象不一致 | 拦截结果并记录异常，提供人工路径 | 不先展示再修复 |
| 关键金额、单位或状态缺失 | 不输出推算结论，提供正式查询 | 不补造币种或成功结果 |
| 官方业务入口不可用 | 给出银行配置的替代渠道 | 不生成替代登录站点或个人收款链接 |
| 人工转接失败 | 提供有效服务时段、官方电话或正式工单 | 不编造排队时长或已连接状态 |
| 投诉提交超时且结果未知 | 先核对状态或按工单幂等机制处理 | 不直接多次提交或显示已受理 |
| 语音权限拒绝或识别失败 | 切换文字，可重新录制 | 不降低账户与企业权限要求 |
| 评价失败 | 保存可重试状态，不打断咨询 | 不将评价失败视为投诉处理失败 |

重试次数、接口超时、网络切换与最终失败提示以技术评审确定，不能让后台重试使用户无限等待。异常日志记录必要定位信息，排除认证凭证和未授权明细。

### 15.1 演示与正式服务的降级口径

| 情况 | L0/L1 本机验证 | L2 及后续正式对客服务 |
| --- | --- | --- |
| 银行知识未就绪 | 仅演示资料，明确未获银行审核；不提供真实业务结论 | 受影响主题不自动回答，提供已批准正式路径；知识就绪前不开放该主题 |
| 查询包未开通 | 说明未接入，无模拟余额/状态 | 给出适用公开说明及有效正式查询入口 |
| 人工/投诉未接入 | 说明未连接、未受理，不产生回执 | 可使用已批准的正式电话、渠道或受理入口替代集成，但须逐项验证；不能仅显示未接入即算承接通过 |
| 紧急入口缺失或失效 | 标明目标银行入口未配置，测试公开提示及不编造状态 | 关键入口与替代路径未通过时阻断受影响渠道/能力发布，不把泛化建议当有效银行紧急路径 |
| 模型或音视频失败 | 返回明确失败/文字降级状态，真实模型验证仍记待验 | 保留合格审核文字与正式路径，不能因展示故障影响紧急或人工服务 |

正式入口校验需覆盖银行批准地址、渠道可用性、服务时段、失败替代及维护责任。具体电话号码和链接由银行提供，不从模型生成。

## 16 数据保护与审计

### 16.1 数据分类与处理依据

| 类别 | 举例 | 产品处理规则 |
| --- | --- | --- |
| 公开银行知识 | FAQ、已公布产品规则、网点资料 | 审核后发布与版本维护 |
| 客户与企业业务信息 | 账户、账单、交易状态、融资进度、企业资金 | 认证、授权、字段限制、受控展示和访问审计 |
| 自然人信息 | 个人客户、企业经办人、联系人身份与联系方式 | 按适用法律和银行制度确认处理依据与必要范围 |
| 认证要素 | 密码、验证码、安全介质口令、令牌秘密 | 不进入聊天、模型上下文、口播或运营分析 |
| 运行与审计记录 | 意图、来源版本、调用结果、授权判断、交接与异常 | 分级访问、脱敏、确定保留与删除规则 |

金融账户相关自然人信息属于敏感个人信息范围，处理需有明确必要性和保护措施；同意及其他合法处理依据应按具体场景判断。[个人信息保护法第十三条及第二十八至三十条](https://www.cac.gov.cn/2021-08/20/c_1631050028355286.htm)提供法律背景。企业数据还涉及银行业务保密与企业授权制度，不能将纯企业数据一概归为自然人敏感信息。

### 16.2 数据流与供应商

每个链路明确哪些信息到达聊天服务、知识检索、语言模型、语音识别、TTS、数字人、RTC、银行接口与坐席系统。默认不向数字人供应商发送原始私有金额或明细，必要例外需单独审核。

客户信息是否供模型推理、知识优化或训练使用，需要分别核定目的与依据；服务所需处理不自动等于训练授权。本期默认不把个人或企业会话用于模型训练，外部服务的数据保留与再利用配置需可验证。

输入和使用记录应受保护，非必要信息不应过度收集。[生成式人工智能服务管理暂行办法第十一条](https://www.cac.gov.cn/2023-07/13/c_1690898327029107.htm)提供相关背景；服务适用、备案与评估事项按部署场景由银行核定。

### 16.3 留存与访问

会话文本、原始语音、转写、口播音频、查询缓存、工单与审计记录分别制定保留期限、可访问角色、导出规则和到期处置。房间保留时长不作为这些数据的保存期限。

公开答案口播可按授权回放；客户原始语音与私有查询内容不因上一版要求口播回放而默认长期保存。数据访问、导出和纠错删除请求走银行受控流程，法定或业务保留事项由相关部门核定。

### 16.4 审计要素

必要审计信息包括客户类型、当前业务上下文的受控引用、角色与授权判断、答案来源版本、工具类别与结果状态、时间、人工转接、投诉回执及异常类别。

银行业务标识与运行追踪标识分开，日志不能包含可用于登录的秘密。留存查询状态与权限依据不要求记录全部原始金融数据。

### 16.5 安全测试

测试覆盖跨个人、跨企业、跨账户、角色越权、权限撤销、提示注入、伪造工具结果、外部链接诱导、敏感口播、过期缓存与导出权限。

客户输入或知识材料中包含“忽略权限”“切换另一企业”“显示后台凭证”等文字时，仍执行服务端授权规则。工具、知识及可信状态有明确来源，普通对话不能伪造银行审批或身份状态。

### 16.6 留存与访问矩阵

| 数据 | L0 已定规则 | 生产要求及关闭条件 | 访问与到期处理 |
| --- | --- | --- | --- |
| 演示会话与脱敏消息 | 本地保存自会话创建起 7 天，访问不延长期限 | 不沿用为统一生产期限；银行按目的、依据与制度核定 | 按本机归属凭证访问；到期不可读取；服务运行时启动及定期清理，停机后的再次启动先清理 |
| 模型输入及输出 | 不真实调用，不产生模型供应商会话留存 | L1 前确认最少必要输入、服务方存储/训练配置和删除方式 | 后端受控访问，不把原始凭证送模型；异常记录脱敏 |

| 公开口播音视频 | 不产生 | 核定资料授权、复用、标识、留存及下架联动 | 仅批准资源可回放；失效内容停止新使用与播放 |
| 私有查询与缓存 | 不查询、不产生 | 每包核定时间窗口、授权变化、存储和清除规则 | 认证失效即时阻断和清除运行展示；审计记录按独立制度处理 |
| 人工交接及投诉工单 | 不提交真实交接或工单 | 按坐席/工单系统与相关制度确定期限、纠错、撤销及访问 | 只向有业务权限岗位传递；到期或删除流程由银行核定 |

删除范围限于已批准的到期数据；法定、合同或争议保留事项按银行核定程序处理。脱敏不等于匿名化，也不免除必要访问控制。生产矩阵中任何待定项须在对应数据开始处理之前关闭。

### 16.7 数据流与供应商核对

| 链路 | L0 状态 | 后续允许范围与检查 |
| --- | --- | --- |

| 原始音频至识别 | 关闭 | 单独核定原始音频接触、传输、存储与转写的范围 |

每条开启链路需有负责人、供应商或银行系统、数据字段、处理目的、传输/部署位置、留存、再利用配置及可核对证据。当前供应商、生产地域、费用和真实数据权限均未批准，不以本表生成接入授权。

### 16.8 同业增量产生的数据

CF01–CF03 若在后续 L0 切片实现，目录与推荐依据仅为当前公开对象/主题、受控知识和能力配置。必要的导航状态、卡片引用及取消状态附属于演示会话，按原会话创建起固定 7 天到期，不因点击、派生记录或重新打开而续期；实际进程重启和到期清理需增量验证。不新增外部分析平台或独立长期点击轨迹。

CF04–CF10 在对应正式包开通前，须补齐任务/摘要/续接标识/评价等数据的必要字段、权限、保存位置、期限和清除规则，并与第 16.6 节一致。受控引用也可能关联个人或企业信息，不按公开资料处理。正式留存不能直接套用 L0 的 7 天。

## 18 会话管理与评价

### 18.1 后台展示

会话类型沿用现有机器人和人工服务体系，增加数字人是否参与、个人或企业类型、业务域、人工接管、异常类别及可访问的关联记录。

会话中的数字人参与标记在成功展示后记录，表示历史上曾使用数字人；当前是否播放与历史参与分开。客户类型和企业上下文切换应形成事件记录，禁止把多个企业私有消息合并成无权限边界的后台视图。

后台可查看审核图文、实际使用的口播文本和来源信息。音频回放只覆盖批准留存的资源，不能让无业务权限的运营人员回放私有明细。

### 18.2 评价字段

| 字段 | 说明 |
| --- | --- |
| 服务类型 | 智能文字、数字人、人工，实际枚举待银行确认 |
| 客户类别 | 个人或企业，按本次评价的业务上下文 |
| 业务域 | 账户、信用卡、个人贷款、对公结算、企业融资等 |
| 评价时间与等级 | 等级枚举待评审 |
| 评价理由 | 准确性、理解程度、体验、人工承接等选项及可选补充 |
| 问题是否解决 | 与满意度分开采集，可选择未解决 |
| 人工邀评信息 | 是否邀评、时间和渠道，按银行已有机制 |

数字人评价不能替代投诉受理。用户未评价不影响继续服务；紧急状态不主动弹出评价。转人工后的评价分别归因或按明确规则合并，不能仅凭最终页面属于数字人归因。

### 18.3 反馈与知识修订（CF10）

在既有评价中区分“答案不清楚”“资料疑似过期”“找不到功能”“未解决”“人工承接问题”，具体枚举随 Q23 冻结。只关联必要的消息/知识/能力版本、服务对象和实际服务类型；补充文本按敏感输入规则处理，不把整段客户资料复制到运营记录。

反馈可进入有权限人员的待核对清单。知识维护人核对来源，业务审核后发布或下架，再用相关失败样例回归；用户差评或模型判断不能直接改写生效知识。可优先复用银行已有知识与评价系统，不要求新建独立运营平台。

“未解决”不等于投诉提交，“已反馈”不等于银行已受理投诉。紧急及人工入口始终可达，未评价不影响继续服务。当前 L0 不新增评价后台或外部反馈发送。

## 19 运营指标与发布

### 19.1 指标建议

以下为本版新增运营设计，目标值待银行提供基线后确认。个人与企业按业务和渠道分别统计，不混用解决率。

| 指标 | 口径或要求 |
| --- | --- |
| 有依据回答覆盖 | 抽样回答中可追踪到有效知识或权威接口的比例 |
| 业务准确率 | 按审定样本检查金额、日期、费用、产品类型及状态解释 |
| 公开咨询解决情况 | 客户反馈与人工复核结合，不以模型自报解决为唯一依据 |
| 查询成功率 | 按开通的查询包计算成功响应，权限拒绝与系统失败分开 |
| 人工承接成功率 | 客户需人工时成功进入对应队列或正式替代路径的比例 |
| 紧急路由质量 | 识别与路由测试、响应及时性以及误报情况 |
| 数字人可用性 | 初始化、播放开始和同步超时，独立于银行业务可用性 |
| 投诉受理一致性 | 页面回执与工单实际状态一致，重复与遗漏单独统计 |
| 服务满意度 | 个人与企业、智能与人工分别分析 |
| 越权与数据泄露事件 | 记录数量、影响和整改；测试严重缺陷作为发布阻断项 |

降低转人工率不作为唯一优化目标，不能为提高自动解决率而隐藏人工入口或漏转紧急问题。

### 19.2 参数与非功能目标

| 参数 | 本版处理 |
| --- | --- |
| 普通答案同步等待 | 建议初始 2 秒，可配置，经体验与技术评审确认 |
| 数字人房间容量 | 重新按银行峰值、保留资源与供应商能力压测；V1.0 的 30 不作为生产值 |
| 房间保留时间 | 可配置候选，V1.0 的 20 分钟需重新评估；与认证有效期无关 |
| 银行接口时延和重试 | 各查询包单独定义，不以口播同步时间代替 |
| 认证与企业权限时效 | 采用银行身份与权限制度，当前值待确认 |
| 并发、可用性与恢复目标 | 按渠道与业务分别确定，未填写数值不作为已承诺指标 |
| 终端兼容 | 个人手机银行、企业网银及批准 H5 的具体版本待渠道评审 |

### 19.3 发布条件

L2 银行试点先开放两类客户评审通过的公开咨询、正式入口与人工承接或正式替代路径。每个私有查询包在身份、权限、数据源、供应商数据流和相关验收通过后独立开启。

上线前完成银行业务与知识审核、数据处理评审、数字人标识、紧急服务入口校验、个人及企业隔离测试、人工承接和回退演练。严重越权、错误资金状态、凭证泄露和紧急路径不可达等缺陷未解决时，不发布受影响能力。

以上是本版提出的发布门槛，具体审批部门和流程按银行制度确认。

### 19.4 开关与回退

公开咨询、数字人展示、语音、个人查询包、企业查询包与业务入口按能力独立控制。关闭数字人仍提供文字咨询；关闭私有查询停止工具调用并清除失效展示；知识下架立即影响新回答及待播放答案。

已进入银行正式业务页面的操作不由客服回退自动撤销。客服只更新自己管理的入口、会话、消息与查询状态，正式业务系统继续执行其控制流程。

### 19.5 指标测量与费用

| 范围 | 当前基线或测量方法 | 目标及冻结方式 |
| --- | --- | --- |

需要冻结的参数须记录负责人、方法、目标、确认日期和触发复评的条件。待定值不写成已达成的承诺。

### 19.6 同业增量效果测量

目录与导航验证用户能否从个人/企业入口找到六类演示主题、理解能力状态、返回或取消；卡片验证用户能否区分说明、入口和查询结果。后续本机体验记录样例、完成/失败、误解点及原因，目标值经产品经理实际评价后确定，不复制同业宣传数字。

正式试点分别计量有效咨询中未解决比例、有效转人工请求中的实际接管比例、已授权查询中的真实返回比例，以及导航任务中的入口展示/发起跳转/可信办理结果。点击率、播放完成率不充当解决率或业务成功率。CF07 未开通时续接指标记不适用，不能填零冒充已测。数据统计范围与保留期限按 Q19、Q24 确认，不为本次 PRD 新增埋点。

### 20.3 执行、证据与阻断规则

1. 每次验收先冻结所测版本、交付包、模型契约、知识版本、接口及目标终端，记录执行人、日期、结论和证据路径。
2. 结果用“通过、未通过、待验、不适用”记录。不适用须说明对应能力确实未开放，并检查未开通的降级状态；生产必需的紧急或人工正式路径缺失不能记为不适用。
3. P0 为安全、权限、凭证、错误资金/业务结论、误导、关键紧急路径或相关强制标识等阻断项；发现时不发布受影响能力。P1 为对应已声明功能的必要验收，未通过不得宣布该交付包完成；不以级别较低为由跳过。
4. 程序测试可使用 mock；真实模型每种契约及关键链路须真实冒烟，银行接口和人工回执须在批准环境取得相应真实服务结果。三种证据分别标识，不相互替代。
5. 本机截图证明页面可用，不能单独证明银行审核、真实身份、供应商数据流或工单受理。保存记录、模型、接口、工单和播放证据在权限允许范围内核对，证据不包含秘密和原始私有明细。
6. 产品经理对 5 到 10 条真实模型样例按第 19.5 节评价，标记不能接受项；标准写入台账后再判断模型效果是否通过。
7. 证据包保留关键截图、可自行核对的步骤与阶段闸门表；原始日志不放入面向产品经理的证据包。任何能力未验证都保持真实状态，完整产品交付须所有适用交付包与验收项满足要求。
