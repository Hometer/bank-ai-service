## 1. 本轮用户与目标

沿用本机个人/企业公开咨询及非敏感人工样例。当前模型选资料、后端显示整条演示说明；有限追问主要依赖关键词与前缀，一些追问会被改写成旧主题关键词，用户当前问题没有完整参与判断。V1.4 优先改善换种说法、连续追问、主题切换与歧义澄清，让咨询更连贯，并让用户知道哪些问题仍没有资料支持。

## 2. 范围与费用边界

沿用个人开户/存款/贷款及企业开户/对账回单/融资六类演示资料。来源、版本、有效期与“未获银行审核”标记继续保留。没有银行正式资料时，不编造具体材料、利率、费用、资格、时限或操作步骤。

本轮提升当前问题的理解、上下文判断及回应方式，不承诺扩充六类资料的业务事实。资料较短时，连续追问具体渠道、费用、材料或时限仍可能得不到确定答案；能够准确说明缺少什么依据，属于应验收的正常结果。

只扩展当前后端与最小验收页；本轮不因版本升级自动开启正式前端、银行接口、真实人工/投诉、音视频或云资源。原接口、旧会话、导航和安全提示须兼容。

费用授权仍仅为既有 DeepSeek、总调用费上限 1 元及最多 20 次请求（含重试）的人工非敏感验证；不因 V1.4 重置预算或请求计数，不自动新增费用。开发前须核对新增模型输入/输出及样例是否仍在既有授权内；无法满足时先完成离线工作，再明确列出具体待确认变化，未经确认不扩大使用范围。

V1.3 中“付费调用为 0”“模型未接入”等描述保留为当时快照。当前受限真实模型授权及实际完成范围以项目状态 D4 和 V1.3 收口证据为准；本版不据此增加任何新的费用授权。

### 3.1 回答方式与资料边界

正常公开咨询按以下顺序组织；不要求每条回复都使用固定标题：

1. **回应当前问题**：有依据时给对应说明；缺依据时直接指出当前不能确认的具体事项。当前问题必须参与判断，不能被旧主题关键词替代。
2. **相关说明与限制**：仅引用与当前问题有关的有效演示内容，保留必要条件和风险提示。不能因主题匹配就推断该主题下所有细节都有答案。
3. **来源与下一步**：展示资料名称、对象、版本、有效范围和演示标记；按现有受控配置提供相关问题或主题选择。无正式银行入口时明确未配置，不生成电话、网址或办理路径。

| 情况 | 应有表现 | 不应有表现 |
| --- | --- | --- |
| 资料支持当前问题 | 回应对应事项，保留必要限制并关联来源 | 只回显整条资料，让用户自行找答案 |
| 只有部分问题有依据 | 分别标明有依据的说明与不能确认的部分 | 用一个来源为所有内容背书，或把可答部分一并笼统拒绝 |
| 已确认主题，但所问细节没有依据 | 保持有效主题，说明具体缺口，允许继续问其他相关问题 | 反复问已明确的对象/主题，或补造细节 |
| 对象、主题或指代不清 | 提出消除歧义所需的具体问题 | 将没有资料误当成用户没说清，一直要求补充 |

例如，个人开户后问“会收多少钱”，预期首先说明“现有演示资料无法确认开户费用”，再按实际资料展示相关说明和来源。此处为拟定表达示例，不是真实模型结果，不承诺银行实际收费情况。

答案可由确定性代码及受控资料组织。新增模型/后端契约在技术适配中冻结；本次文档补充不开放自由生成金融解释，不授权模型增加业务事实或改变固定安全提示。

### 3.2 有限澄清、取消与恢复

- **本轮推荐默认值**：针对同一个尚未解决的歧义，连续最多发出 2 次澄清提示，每次只询问必要的对象、主题或指代，不索要账户号、密码、验证码等信息。该值用于避免无限追问，不是模型效果通过标准。
- 第 2 次提示后，用户补充的信息足以判断则继续回答；仍不足时说明“当前无法确定所指业务”，提供现有六类主题选择或取消入口，不再自动发出第 3 次同一歧义的澄清。
- 模糊补充、无进展回答、刷新、服务重启及模型失败不重置同一歧义的次数。澄清状态和次数与会话一起持久化，固定 7 天期限不因追问续期。
- 明确解决歧义、明确切换到新问题或取消后结束本次澄清。不得靠改写同一个模糊问题绕过次数限制；用户之后主动提出清楚的新问题可以正常咨询。
- 取消终止当前澄清/导航及其在途答案的展示资格；保留允许展示的历史，但不把被取消的主题自动恢复成后续指代依据。刷新或重启不得重新弹出已取消的追问。
- 取消普通咨询不关闭有效紧急提示；人工、私有查询、敏感输入和紧急问题仍先走既有保护路径。拒绝提供敏感信息不影响公开咨询。

### 3.3 用户纠正与多个公开问题

| 输入或事件 | 处理规则 |
| --- | --- |
| “不是开户，是存款”“你理解错了，我问的是企业融资” | 用明确纠正重新判断，旧主题不再作为本次答复依据。仅说“你理解错了”但没给出替代主题时，询问具体纠正内容，不猜测 |
| 个人语境中明确询问企业公开业务 | 沿用 V1.3 第 9.7 节：确认切换，或明确标记本条为企业公开答复；不将个人语境、历史或权限自动套给企业 |
| “个人开户和企业开户各要了解什么” | 在六类资料范围内拆分两个明确问题，分别标记对象、相关说明、缺口与来源；不能只选其中一个，也不能把两个对象混成一份结论 |
| 多主题回答后问“那还需要什么” | 询问指的是哪个对象/主题，不默认使用最后一条；明确回答后只延续选定的有效主题 |
| 新问题明确切换主题，但仍包含旧主题词 | 按完整当前问题判断，不能因旧关键词命中而压过明确的新意图 |

必要公开上下文只包含已确认对象、主题、来源/版本及当前澄清所需信息；不向模型发送完整历史，不从敏感、被取消、失效或其他会话内容推导主题。新问题与旧主题冲突时，旧上下文不能覆盖当前明确表达；无法消除歧义时按第 3.2 节处理。

### 3.4 模型失败与额度不足时的体验

超时、初始化失败、结构不合法、非法资料编号或额度不足时，应结束等待并给出可理解的失败/降级提示。只能在既有有效资料和保护规则内提供确定性的说明或主题选择，不把无效模型输出展示给用户。

失败不把猜测保存为已确认主题，不重置澄清次数、会话期限或费用台账，也不能让迟到响应恢复已经取消/切换的状态。具体超时、有限重试和接口错误结构在技术开发文档中冻结；重试计入同一请求与费用上限，不能无限等待或连续自动重试。

页面与验收记录应能区分真实模型结果、规则演示及失败后的降级结果。规则降级可单独验收，不计为真实模型通过。

### 4.1 覆盖与证据要求

以上 18 组为验收目录，不等于 18 条 HTTP 请求，也不表示已运行。Q14-01/03/04/10/11/12 覆盖全部六类主题；Q14-02/05/06/07/13/14/15/16 覆盖追问、澄清、切换、纠正及多主题；Q14-08/09/17/18 覆盖持久化、失效、安全及失败边界。每组包含的不同事件须分别记录结果，不能只测一条分支即将整组记为通过。

保留已有 149 条自动化回归，新增针对当前问题与上下文、歧义、主题切换、失效与旧数据兼容的必要测试。149/149 是旧版已留档基线，新版通过数必须以本次实际运行结果为准。故障注入、到期、取消/迟到响应、澄清上限和预算阻止优先用离线自动化验证，不为制造故障消耗真实额度。

真实模型新增契约和新增关键链路须另行真实冒烟，包括六类主题、当前问题与有效上下文的组合、必要澄清及明确纠正/切换。多主题输出若涉及新增模型契约，也须纳入真实验证；没有运行即标“待验”，不能用 mock、旧版结果或规则降级替代。

验收记录至少包含样例编号、必要的非敏感输入/前置状态、实际答案、来源、处理模式、请求次数、结果和未覆盖分支。来源、结构合规、效果评分及费用分别记录；不保留敏感原文或密钥。

### 4.2 真实验证请求安排

2026-10-03 既有证据记录已使用 8/20 次请求，保守费用预留 0.0864 元；据此最多剩余 12 次请求。此为留档快照，未在本次 PRD 编辑中实时读取费用台账，不代表执行时仍有相同余量。

1. 实施前核对同一持久化台账的实际剩余次数与费用，以及新版输入/输出长度限制。金额有余额但次数用完，或次数有余额但费用不足，都停止付费请求。
2. 若仍余 12 次，建议最多安排 10 次正常验证请求，留 2 次给必要重试；这是验证计划默认值，不是新增额度，也不要求为用完额度主动重试。实际费用不足时进一步缩减或停止。
3. 阶段开发文档须逐步列出真实验证序列：关联 Q14 编号、前置状态、每步是否调用模型、预期模式及请求/费用预留。每次 HTTP 请求都计数；不能把多轮会话或包含多次模型调用的步骤当成一次。可以用前一步已取得的有效主题覆盖下一步切换/追问，不伪造前置验证结果。
4. 仅恢复主题、查看历史、刷新及规则保护等不需要模型的步骤应分别标明，不能计为真实模型效果证据。多主题若需要多次调用，必须逐次预算。
