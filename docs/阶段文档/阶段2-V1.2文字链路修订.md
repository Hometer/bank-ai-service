## 一、阶段目标

在现有 L0 文字演示上补齐 LV13 至 LV16，并回归 LV01 至 LV12：输入保护 → 服务对象与主题澄清 → 生效演示知识 → 标记答案和来源 → 原子保存会话/主题/公开紧急状态 → 刷新及重启恢复。

产出为追加数据库迁移、规则及上下文处理、统一接口、最小验收工具、自动化/实际服务验证、README 和证据包。不开展真实模型、银行查询、真人转接/投诉提交、音视频、正式前端或云部署；原 PRD 完整要求继续留档。

## 二、技术适配摘要

沿用 Python 3.12、FastAPI、Pydantic、SQLAlchemy、SQLite、Alembic、pytest 和原生 HTML/JS/CSS。主题与紧急状态必须可恢复，所以继续使用已有数据库，不更换技术栈或引入向量库。页面仍是本机验收工具。敏感检测与状态规则集中于后端，浏览器只负责展示与明确关闭动作。

## 三、技术栈与模型

本次强制演示模式进行验证，外部调用为 0。保留原结构化知识编号模型契约、校验、有限重试和错误兜底；模拟测试继续覆盖，不提供厂商或模型效果结论。澄清与多意图采用有限的受控文字规则，不能识别的表达明确澄清/拒答，不把演示规则称为通用语义模型。

## 四、环境与配置

沿用 `.venv`、锁定依赖及 `.env.example`；不读取或输出真实密钥，不增加供应商。主验收地址 `http://127.0.0.1:18763`，仅绑定回环地址。测试及迁移检查使用独立临时数据库，保留原 `data/bank-demo.sqlite3`。会话到期仍为创建起 7 天，访问不延长。无需产品经理现在提供 Key。

## 五、项目结构

- `app/service.py`：原规则与模型边界，细化敏感判断。
- `app/consultation.py`：受控对象/主题与上下文规则，返回结构化分项及下一主题。
- `app/schemas.py`：追加澄清、分项、主题和紧急状态结构。
- `app/db.py`、`alembic/versions/0002_consultation_state.py`：追加兼容迁移及恢复。
- `app/main.py`：归属权限、并发版本检查、状态与消息事务。
- `app/static/`：分项对象、澄清、持续紧急提示及明确关闭，仍为最小工具。
- `tests/`、`scripts/verify_restart.py`：新增质量与迁移/重启验证；原测试保留。
- `scripts/verify_browser.mjs`：通过 ego-browser 的页面操作、延迟响应与截图验证。

## 六、数据、资产与状态

`conversations` 追加 `context` JSON 与 `revision` 整数，旧记录默认空主题、版本 0。主题结构只包含生效知识编号及个人/企业公开类型、澄清次数，不保存额外凭证。主题指代必须重新核对知识适用范围/生效状态；明确新问题替换旧主题，取消澄清清空主题，控制类/未知问题不借用旧主题。

追加 `safety_notices`：浏览器归属哈希为主键，`active` 布尔、`revision` 整数、`updated_at` 和 `expires_at`。仅保存通用公开紧急提示状态，不保存风险原文、客户账户或银行参数。触发后到期时间取触发会话原定到期时间；普通答案、切换、刷新不延长或解除。到期读取为无有效提示，启动/定期清理过期状态。

状态转换为无提示/已关闭 → 紧急输入后激活；激活 → 普通咨询后仍激活；激活 → 明确关闭且版本匹配后已关闭；新的紧急事件再次激活并提高版本。关闭只表示停止显示，回复必须明确未确认风险消除。服务类型切换保留通用公开提示，绝不把企业私有数据带入另一语境。

消息与上下文同一事务提交；请求处理后再检查归属、到期和会话版本。并发旧请求不能覆写新主题，返回 409 `CONTEXT_CHANGED`；关闭旧版本紧急提示返回 409 `SAFETY_CHANGED`，需重新核对最新提示。新增字段和表不删除旧消息，迁移不重建已有表；在独立旧版数据库验证原历史保留。本轮测试不写入原有演示数据库，用户下次正常启动时自动应用已验证的追加迁移。

紧急输入不依赖旧咨询主题，也不能被普通主题版本冲突压制：在归属/到期仍有效时原子保存紧急消息、清空主题并激活通用提示。该优先规则通过并发对照单独检查；不能用于绕过归属或查询权限。

## 七、API 设计

所有路径保持 `/api/v1`，原接口和原字段保留。错误为 `{"error":{"code":"...","message":"..."}}`，不泄露堆栈。

| 接口 | 请求 | 响应及追加字段 | 错误 |
| --- | --- | --- | --- |
| GET `/sessions/{id}` | 原路径与归属 Cookie | 原历史；会话追加 revision，回答可含分项/澄清 | 原 401/404/503 |
| POST `/sessions/{id}/messages` | 原 `text` | 原 user_text/answer；追加 safety。answer 保留 text/sources，可含 parts；kind 增加 clarification | 原错误，追加 409 CONTEXT_CHANGED；请求处理后过期仍 404 |
| GET `/safety` | 归属 Cookie，无正文 | active、revision、updated_at、expires_at；不含原始风险文本 | 401/503 |
| POST `/safety/dismiss` | expected_revision 非负整数；归属 Cookie | 最新紧急提示状态，明确 action 为关闭显示 | 401、422、409 SAFETY_CHANGED、503 |

分项只允许个人/企业公开答案，字段含类型、结果类别、受控文字和来源。总体 text 同样标明对象，便于旧客户端读取。普通 JSON 响应，无 SSE、上传或银行工具。

## 八、Prompt 设计

原 `prompts/select_knowledge.txt` 与知识编号输出契约继续使用，不增加金融自由改写。敏感披露在存储与模型入口前整体屏蔽；紧急意图由确定性代码保留，原文不进入模型。新增上下文只能选择仍生效且类型一致的知识，模型不能扩大候选集合或修改身份。

## 九、验收界面

页面明确当前咨询类型仅为公开语境。未选择对象时提示先选择，不隐含账户身份。显示每个公开分项的个人/企业对象及来源；未知指代显示澄清。紧急提示置于普通咨询记录外，普通答案和切换不覆盖；“关闭此提示”通过受控接口保存结果，注明关闭不代表风险解除。

接口迟到响应按当前页面版本和会话编号检查；安全状态按后端 revision 合并，旧结果不能复活已关闭提示。恢复历史重新获取安全状态。前端全部使用 textContent，不回显凭证原文。检查 1440 与 390 宽度及实际迟到响应。

## 十、测试要求

保留旧测试，新增业务场景：明确跨对象公开问题；个人/企业混合问题；无主题指代澄清；可靠主题追问；多主题继续追问澄清；取消与连续无法澄清的降级；主题到期/禁用不复用；重启主题恢复。

敏感检测采用虚构对照：密码/验证码流程可咨询；年份、期限、带单位金额可讨论；明确凭证披露、API key、卡号、联系方式仍屏蔽；紧急+凭证只保留公开求助；模型模拟客户端不得收到被拦截内容。

安全状态测试包括归属隔离、普通问题不解除、刷新/切换/重启恢复、明确关闭、旧版本关闭被拒绝、新紧急重激活、到期删除。会话并发版本冲突不产生半条消息。迁移从 0001 保留原记录。

运行 pytest、mypy、ruff、JS 语法、实际进程重启/到期清理及 ego-browser 的桌面/移动/延迟响应检查，提供截图。真实模型保持待验；无费用调用，不把有限规则样例通过作为生产语义准确率。

## 十一、产品经理验收清单

1. Finder 双击 `启动演示.command`，浏览器打开本机地址；看到“规则演示”与“真实模型待验”。
2. 选择个人，发送“开户需要什么材料”；看到个人演示来源。接着“那需要什么”，应延续有效主题。新建会话问“那需要什么”，应要求澄清。
3. 个人语境问“企业开户材料”；答案明确标为企业公开咨询。问“个人贷款和企业融资都要哪些材料”；看到两个分项及各自来源，服务选择不变。
4. 问“忘记密码怎么办”“验证码收不到”“2026年资料哪里查”；不被当作已泄露凭证。只用虚构“验证码是123456”测试，原文不出现在历史。
5. 问“银行卡被盗刷了”，看到持续公开求助提示；再问开户、切换企业、刷新，提示仍在。点击“关闭此提示”，看到未确认风险解除的说明；刷新后不自动恢复旧提示。新的紧急问题再次显示。
6. 关闭演示终端后重新启动，允许的主题与提示状态恢复；结束时 Control+C。不得输入真实客户资料。
