# V1.4 技术适配声明

日期：2026-10-03。配套：[V1.4 PRD](../PRD/银行智能客服_PRD_V1.4_文字问答与多轮追问增量.md)、[阶段技术开发文档](阶段2-V1.4文字问答与多轮追问.md)、[项目状态](../项目状态.md)。本文件在 V1.4 业务代码修改前创建；描述开工前确定方案。2026-10-03 已据此实施，完整程序/真实验证与证据见阶段技术开发文档；新版十条整体效果评分已确认均为 3/3（满意），真机反馈待验。

## 1. 产品形态判断

- 产品类型与核心任务：本机个人/企业公开知识咨询，在既有六类演示资料内理解当前问题、有限追问、明确纠正及多个公开问题。
- 核心交互：多轮对话；歧义最多两次澄清，支持取消、主题切换和恢复。模型不执行办理、查询、授权、对外发送或自主付费动作。
- 开发路径：在现有后端和原生验收页上做最小纵向切片，继续处于阶段 2；不进入正式前端或上线。
- 当前范围：T14-01–08 和 Q14-01–18。提升回应方式，不扩充银行业务事实；无资料时准确说明具体缺口。

## 2. 采用的默认方案

| 方案 | 采用原因 |
| --- | --- |
| 现有 Python 3.12、FastAPI、Pydantic、pytest | 已满足请求校验、结构输出和自动化验证，不升级依赖或重建项目 |
| 现有 SQLite、SQLAlchemy、Alembic 与会话版本条件更新 | 复用事务、归属隔离、固定 7 天留存及迟到响应保护 |
| 原生 HTML/JS/CSS 验收页 | 只增加判断多轮效果所需的状态、取消和处理模式展示 |
| 既有 DeepSeek `deepseek-flash` 非思考模式 | 延续 D4 授权，不增加厂商或费用范围 |
| 模型作结构化路由，后端组织答案 | 模型只选择有效资料编号和问题类别；后端引用原文、解释资料缺口，不开放自由生成金融解释 |
| 全部旧测试保留，必要行为断言随 PRD 更新 | 第二次澄清和明确多主题是已要求的行为变化；补充更强边界测试，不删除测试或放宽安全检查 |

## 3. 触发的按需模块

- 持久化咨询状态：由 T14-02–04/07/08 触发，扩展已有 `conversations.context` JSON，包含来源绑定、待澄清候选、次数及状态；不引入新数据库或独立历史副本。
- 新模型路由契约：由换种说法、当前问题参与判断、问题类别和多主题拆分触发；同一条消息通常只调用一次，最多两次 HTTP 尝试含重试。
- 最小界面调整：由澄清、取消及真实/规则结果区分触发；不引入正式前端脚手架、运营后台、队列、向量库或 SSE。

## 4. 偏离或暂缓的默认方案

| 默认项或后续能力 | 当前处理、原因与影响 | 重新评估条件 |
| --- | --- | --- |
| 正式 Web 前端栈 | 延续现有原生页面，当前核心链路尚需真实验证；无生产前端打包环节 | 进入阶段 3 并取得核心链路验收 |
| 向量检索、动态工具规划 | 六条受控资料无需增加检索基础设施；无授权银行工具 | 知识规模或已确认任务确实触发时 |
| 自由生成业务解释 | 使用后端固定缺口提示与原文摘录；资料较短，部分追问仍无法确认 | 有银行审核资料、明确改写权限及独立验证后 |
| 银行认证、私有查询、真实人工/投诉、音视频、云部署 | 继续保留原开通条件，当前显示真实未接入状态；不影响本轮公开文字验收 | 相应交付包条件及预算另行就绪 |

保留现有数据库与 HTTP 接口，字段作兼容追加；不重命名或删除旧接口、旧数据和已有功能。没有新的外部平台、资料上传类型或费用授权。

## 6. 需要产品经理决定的问题

无新增影响本轮目标用户、成本、安全、隐私或交付范围的待定项。用户已要求按评审建议完善 PRD，并指示进入下一步、先文档再开发；六类资料、本机、7 天留存、既有费用及两次澄清默认值随当前方案执行，不重复索要确认。
