# 阶段 2 技术开发文档｜文字核心链路

日期：2026-10-02。只实施已确认的本机文字切片，完整银行 PRD 的其他要求继续保留。

## 一、阶段目标
输入咨询 → 敏感输入检查 → 个人/企业知识筛选 → 规则演示回答或降级提示 → 保存脱敏会话 → 页面可查看来源与历史。运行服务、自动化测试、重启恢复及到期删除验证。真实模型待验，阶段 2 保持未完成。

## 二、技术适配摘要
沿用《技术适配声明》：Python 3.12、FastAPI、Pydantic、pytest；会话与消息使用 SQLite、SQLAlchemy、Alembic；单个 HTML 是临时验收工具，不开发正式前端。

## 三、技术栈与模型
本轮默认 `MODEL_MODE=demo`，回答由有限的本地知识与规则产生，显式标注“规则演示，非真实模型”。模型厂商与模型名暂未选定。兼容调用适配器只允许返回知识编号或 null，不让模型编造业务答案或执行工具，测试用 mock 验证其异常与输出契约，不进行真实请求。

## 四、环境与配置
- Python 3.12 的 `.venv`；依赖安装后锁定实际版本到 `backend/requirements.txt`。
- `.env.example` 仅含空密钥；`.env` 和 `data/` 排除 Git。
- 本机端口为 18763，绑定 `127.0.0.1`；8000 与 8765 已被其他程序占用，未对其作修改。
- 本轮无外部服务依赖、无付费请求，不要求产品经理提供 Key。
- 配置：数据库位置、模式、模型地址/名称/密钥、调用超时与最多 2 次尝试。留存按已确认的 7 天固定执行，不暴露给客户改动。

## 五、项目结构
`backend/app/` 保存配置、校验、数据库、规则与模型服务、API；`knowledge.json` 保存演示知识；`prompts/` 保存受版本管理的模型选择提示；`static/` 保存最小界面；`backend/tests/` 保存自动化测试；`backend/alembic/` 保存数据库迁移。

## 六、数据、资产与状态
- 会话：UUID、浏览器归属凭证的 SHA-256 摘要、客户类型、创建时间、到期时间。消息：会话引用、用户/客服角色、脱敏文本、结果结构及时间。
- 浏览器归属凭证随机生成，放入 HttpOnly、SameSite=Strict Cookie；不向页面 JS 或响应正文返回。属于本机演示权限凭证，不是银行身份。
- 浏览器请求读取或写入会话时验证归属；切换个人/企业使用独立会话；客户端切换时丢弃旧请求展示结果。
- 会话自创建起保留 7 天，不因访问延长；数据库维护在启动时及每小时清理到期会话和消息。清理范围仅限已批准的演示会话，不删除用户其他数据。
- 模式：`demo` 或 `model`；结果类别：`answered`、`unknown`、`private_unavailable`、`urgent`、`human_unavailable`、`sensitive_blocked`、`model_unavailable`。路径未配置时保持不可用状态，不声称已连接。

## 七、API 设计
统一前缀 `/api/v1`，错误为 `{"error":{"code":"...","message":"..."}}`，不含堆栈。每个接口均以 Pydantic 定义响应及 OpenAPI 错误结构。

| 方法与路径 | 请求 | 响应 | 错误 |
| --- | --- | --- | --- |
| GET `/health` | 无 | 状态、运行模式、真实模型待验提示 | 503 存储不可用 |
| POST `/sessions` | `customer_type`: personal/enterprise | 会话编号、类型、到期时间 | 422 参数错误 |
| GET `/sessions?customer_type=...` | 可选客户类型 | 当前浏览器未过期会话列表 | 401 无归属凭证；422 类型错误 |
| GET `/sessions/{id}` | 路径编号及 Cookie | 会话、消息与结果结构 | 401 未认证；404 不存在、过期或归属不符 |
| POST `/sessions/{id}/messages` | `text`，非空、最多 2000 字；Cookie | 用户脱敏文本、客服答案、来源、模式及服务入口状态 | 401/404 同上；422 参数错误；503 存储失败 |

未知路由与其他 HTTP 错误也返回统一错误。阻断敏感输入是成功处理的服务状态；模型失败以 `model_unavailable` 给出明确降级结果，不伪造模型答案。无 SSE、无上传、无动态工具或银行写入。

## 八、Prompt 设计
提示文件限定模型仅从当前客户类型、仍生效的候选知识选择 `knowledge_id`，或返回 null。示例 `{"knowledge_id":"personal_opening"}`，禁止额外字段、自然语言、地址或工具。后端解析等价 JSON 代码围栏，Pydantic 严格校验，并再次检查编号在候选集合中；错误或超时最多尝试 2 次，客户端构造失败统一兜底。答案始终来自受控演示知识，不使用模型自拟金融文本。

## 九、验收界面
单页文字验收工具，显示规则模式及未接入能力；个人/企业切换、示例问题、输入、来源、历史、新建会话。页面不显示敏感原文；收到服务端脱敏结果后才渲染输入。纯原生 JS，用 `textContent` 防止把输入或答案当 HTML 执行；限制请求等待并处理失败。检查桌面 1440 像素与移动端 390 像素。

## 十、测试要求
覆盖个人与企业同主题分流、未知问题、私有查询、紧急意图及人工需求优先级、无有效知识、敏感输入不存储不发送、会话凭证隔离、过期删除、重建应用恢复、统一错误、模型输出校验、有限重试、超时与客户端初始化失败。增加实际进程停止再启动的接口恢复检查；自动化 mock 不代替该检查或真实模型验证。

真实模型：本轮不运行，明确待验；未来按个人/企业及每种不同调用契约至少各覆盖一条真实链路，并让产品经理对 5 到 10 条样例打分，记录模型、延迟、用量与费用。

## 十一、验收清单
- 打开本机页面，看到“规则演示”及“真实模型待验”。
- 在个人服务发送“开户需要什么材料”，看到演示来源与银行待确认提示。
- 切换企业，发送“企业开户需要什么材料”，看到企业答案，个人历史不混入。
- 发送“查余额”，看到查询未接入且没有余额数字。
- 发送“银行卡被盗刷了”，看到紧急提示及入口未配置提示，不显示已冻结或已挂失。
- 发送“转人工”，看到未接入状态，不显示已连接或预计等待时间。
- 发送虚构测试输入“验证码是123456”，页面与持久化仅保留屏蔽说明。
- 刷新页面，当前浏览器能够恢复未过期的演示会话。
