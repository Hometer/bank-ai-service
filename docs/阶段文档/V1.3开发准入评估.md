# V1.3 开发准入评估

日期：2026-10-03。输入为[PRD V1.3](../PRD/银行智能客服数字人_PRD_V1.3_同业功能提炼版.md)、[项目状态](../项目状态.md)和已有 V1.2 实现。本文件及配套阶段开发文档在代码修改前创建。

## 结论

可以进入阶段 2 内的 V1.3 本机增量开发，范围限定为 CF01–CF03 的 L0 部分。用户本次已明确要求“先出文档，再进入开发操作”，现有五项边界与技术方案均可沿用，没有阻塞这次开发的业务待定项。阶段 2 的真实模型和产品经理体验验收继续待验。

现有六类知识只有概略公开说明。分步卡仅将有效原文确定性拆为阅读段落，命名为“演示说明分步阅读”，不新增材料清单、办理步骤、网点、利率或银行入口。目录和建议由后端生成，不从客户画像推断。

## 范围与兼容性

沿用 Python 3.12、FastAPI、Pydantic、SQLAlchemy、SQLite、Alembic 及原生 HTML/JS/CSS。只扩展最小验收页，不进入阶段 3 正式前端。依赖不升级、不引入新模型或平台。会话新增可恢复导航字段，旧接口和已有字段保留，旧答案缺少新字段时使用默认值。

测试及浏览器验收使用独立数据库；原演示库保持不动。正常用户下次启动时应用已验证的追加迁移。旧测试保留，仅允许为新增迁移更新迁移版本断言，同时保留原数据完整性断言。PRD 当前未提交的修改继续保留，不覆盖原文。

## 暂缓项

CF04–CF10 及 CX06–22 的正式银行部分继续按 PRD 分期；CF07 仍是可选扩展。本轮不新增真实银行身份/查询、正式链接、人工摘要外发、投诉受理、位置收集、财富推荐、音视频、外部埋点、付费调用或云部署。

## 开发与验收顺序

1. 保存本评估与[阶段开发文档](阶段2-V1.3目录导航与公开卡片.md)，冻结接口和本机默认值。
2. 追加数据结构及受控服务模块，接入现有文字链路和最小验收页。
3. 运行完整自动化回归、类型/Lint/脚本检查、旧库迁移及真实进程恢复/到期验证。
4. 用 ego-browser 检查桌面和手机宽度、目录/卡片/返回/取消及迟到响应，核对截图。
5. 更新 README、项目状态及独立 V1.3 证据包；分别记录本机程序结果、真实模型待验和产品经理体验待验，不宣布阶段 2 全部完成。

风险集中在取消/切换竞态、历史卡片失效、配置损坏及固定留存。由后端版本条件更新、执行前复核、统一错误和真实重启测试约束。无需产品经理重新回答已定的五项边界。
