# 阶段2增量：多银行客服知识扩充

2026-10-03，开发前定义。配套《多银行客服知识扩充技术适配声明》，按用户要求补齐客服问答，继承V1.4安全/数据/费用契约。

## 资料与接口

新目录 `docs/知识库/香港银行客服/` 保存schema版本1.0的补充问答、来源、排除及可读手册；银行ID、香港地区、实体、个人/企业、问题变体、确定性检索规则、答复、限制、出处定位及核对/复核日期必填。独立本地启用清单允许停用单条，不等同银行审核。

继承消息/会话/目录/导航/安全接口，请求及错误 `{"error":{"code","message"}}` 保留。内部Knowledge新增有默认值的FAQ银行/检索规则字段；旧资料指纹保持稳定。health仅增加可选有效条目/银行数量，页面从真实配置显示；来源仍沿用已定义Source/PublicReference结构，不允许任意外链。

新增可选补充路径配置，仅公开知识模式默认启用；原直接Settings及旧演示不自动加载。配置损坏返回既有结构化503，health标不可用，不替换为其他银行答案。文件修改指纹绑定后已存上下文与阅读状态不得冒用旧条目。

## 检索及状态

按明确银行→地区→对象→意图和问题变体匹配。FAQ按银行/对象分组，命中条目返回简短原义改写和限制；有来源才答，未覆盖费用/时间/材料等保留缺口。通用知识只处理明确定义的香港公共问题。无银行名字时先用当前有效银行上下文，否则交银香港；未知地区/银行不借用任何银行条件。一次最多两个明确FAQ事项；单条的重复说法不作多个问题计数。有限追问用来源绑定的条目和焦点选择，不凭空扩充事实。

安全与查询/人工未接入优先；普通取消不关闭紧急提示。公开重置说明允许命中官方FAQ，发送密码/验证码原文仍被既有脱敏代码挡住。固定目录与建议只预填公开问题，不自动发送或执行业务。

## 验证计划

每条新增问答的规范问题经本地实际接口返回对应编号、正文、限制和官方来源；替代表达另选跨银行与主题样例。分别检查银行切换与地区错配、受保护路径、未知价格/审批/个人状态、复合问题覆盖、两次澄清/取消、启用清单与过期/损坏保护、重新启动后会话/银行追问/阅读恢复。339条原测试必须保留并通过；mypy/Ruff/JS/Python检查，四个代表银行及交银默认在桌面/手机宽度浏览器操作。实际样例与用户打分分开留存，本轮没有模型调用。

## 操作与待验

沿用 `启动知识库演示.command` 及18768本机预览；默认问交银香港，其他银行在问题写明银行名字。只用非敏感公开问题。新资料满意度、网络来源未来改版与真机待验；到内部复核日停用，复核不是自动延长。实施结果与证据完成后追加到本文件。

## 用户方向修订（实施前，2026-10-03）

用户反馈“回答倒是没有什么问题”，要求题目以交通银行（香港）为主体，答案可参考其他银行。记录为定性反馈，不代填数字评分。保留同业原始资料供溯源，增加交银主体的通用客服建议层：同业通用处理方法可参考，其他银行费率、额度、认证等待时间、产品条件、SWIFT及App品牌/菜单不得移植成交银事实；地区公共事实标明金管局通用依据。

新增 evidence_role 区分 bank_rule / peer_guidance / regional_guidance。参考条目只能面向交银、带固定说明及真实原发布者；服务器严格限制跨银行来源只用于已标记参考条目，原 bank_rule 归属校验不放宽。前台目录以交银与公共基础知识为主，已有具名同业查询及研究档案保留。示例与验收题改成交银香港，效果重新留待反馈。

## 当前实施结果

原30条保留，新增116条（104条官方FAQ/公共资料、12条交银场景通用建议），合计146条、41个不同网址。交银主体手册70条；前台个人7项、企业8项，具名同业查询及研究档案保留。参考条目标真实发布者与非交银条款，原bank_rule来源归属校验未放宽。

649/649全量（339原有+310新增）通过，原30条在合并启用下仍返回原编号。mypy26、Ruff、JS/Python、两份资料校验通过。两次实际重启恢复交银参考来源/追问、汇丰银行上下文、企业步骤/取消；关闭FAQ的原恢复脚本也通过。四宽度及七组浏览器检查、十条全为交银题目的实际发送通过。没有新增模型请求，原费用policy和全部记录仍18/20。

修正收内地汇款的地区识别、授权撤销语序及FAQ阅读定位。用户新方向调整后，公共支付问题绑定交银场景参考；具名金管局查询仍返回原监管条目。停用、到复核日和来源指纹变化不再引用旧事实；回归均保留。
