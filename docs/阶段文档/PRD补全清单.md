## 必须问（本轮 5 个，均已确认推荐）

### 问题 1：首轮是否面向某一家真实银行？
- 为什么重要：目标银行决定知识来源、品牌、业务规则及正式路径，通用演示不能冒充真实银行服务。
- 选项：A 通用银行场景验证 / B 指定真实银行试点，补充银行名及现有资料。
- 推荐：A，仅使用明确标记的演示知识，不声称银行已审核或接入。
- 不选的后果：B 需先取得该行知识、正式入口及接入授权。

### 问题 2：是否接受首轮只验证文字咨询核心链路？
- 为什么重要：PRD 完整范围包含音视频、数字人及银行系统协作；这与“先跑通一次代码”所需的最小范围不同，不能自行缩减验收。
- 选项：A 文字核心链路先行 / B 首轮包含语音与数字人。
- 推荐：A，首轮验证个人与企业公开咨询、来源追踪、无依据拒答和紧急/人工路径提示；后续验收音视频、私有查询、真实人工与投诉接口。
- 不选的后果：B 还需确定音视频供应商、银行接口及预算。暂缓项仍保留，首轮通过不代表完整 PRD 交付。

### 问题 3：首轮开发的数据与留存边界是什么？
- 为什么重要：真实客户资料会改变隐私、安全、部署及外部模型处理要求；留存期限不能擅自确定。
- 选项：A 仅演示数据 / B 使用真实业务资料。
- 推荐：A，仅人工编写的非敏感样例，不接真实账户、不收集原始音频，会话脱敏后仅本地保存 7 天并到期删除。
- 不选的后果：B 需确认授权、访问权限、部署位置与供应商数据流后再使用资料。

### 问题 4：首轮怎样使用模型及控制费用？
- 为什么重要：模型厂商及费用上限未定；自动化测试通过与真实模型通过必须分别记录。
- 选项：A 暂不付费调用 / B 使用已有模型 API，补充厂商名称与费用上限。
- 推荐：A，首轮付费调用为 0，先验证自动化测试和服务启动；无真实验证时明确记为待验。
- 不选的后果：B 需模型接入及预算，密钥之后仅填本地配置，不发到聊天。A 下后端阶段真实模型闸门未通过，不得宣布阶段完成。

### 问题 5：首轮在哪里验收，是否已有企业认证条件？
- 为什么重要：本机验证、联网多人试用及银行正式上线的身份隔离、费用和审核范围不同。
- 选项：A 仅本机验收 / B 联网试用，补充试用对象、云预算及能否企业认证。
- 推荐：A，暂不部署、不创建云资源；如计划企业上线且能办认证，可并行准备。
- 不选的后果：B 需确认登录隔离和上线方案；创建收费云资源前仍须告知费用并取得确认。

## 已发现的矛盾与资料缺失
- 首轮切片与完整范围：PRD 第 4.2 节保留语音和数字人相关必交付要求，建议的文字切片必须由产品经理批准。批准后只改变先后顺序，不删除这些要求；每个能力按实际接入情况验收。
- 人工提示与人工接管：没有真实队列接口时只能提示未接入状态或提供已配置的正式路径，不把页面提示当作真实连接人工，亦不能视为通过真实人工承接验收。
- 知识真实性：尚无目标银行审核知识、紧急电话、办理地址和查询接口。演示内容不得标记为银行已审核，生产发布前必须取得真实配置和审核。
- 历史来源引用：PRD 第 22.1 节引用的 V1.0 及两份飞书原文留档在当前目录中不存在；V1.1 可作为本轮独立评审输入，历史原方案能力仅按其明确记载理解，不声称已核对缺失资料。若后续验收需追溯原方案，再补来源。
- 模型闸门：即使后续服务能够启动且 mock 测试通过，真实模型冒烟未运行时仍记为待验，后端阶段保持未完成。
