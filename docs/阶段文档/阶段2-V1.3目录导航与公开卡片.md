# 阶段 2 技术开发文档｜V1.3 目录、导航与公开卡片

日期：2026-10-03。配套：[PRD V1.3](../PRD/银行智能客服数字人_PRD_V1.3_同业功能提炼版.md)、[开发准入评估](V1.3开发准入评估.md)、原技术适配声明、通用手册第二和第三部分。本文件先于本轮代码修改创建；末尾实施记录才表示实际执行结果。

## 一、阶段目标

在 V1.2 已验证的 L0 链路上实现：选择公开对象 → 读取该对象的有效演示目录 → 查看有来源的公开卡片 → 分步阅读/相关咨询 → 返回或取消 → 保存并恢复状态。范围为 CF01–CF03 的本机部分，覆盖 CX01–05、CX23、CX24 的 L0 部分及 CX07 不生成私有样例卡的边界，保留 LV01–LV16。

产出为开发文档、追加迁移、受控目录和卡片模块、最小验收页面、自动化及真实进程/浏览器验证、README 与证据。银行接口、真实模型、正式人工、投诉、语音、数字人、外部发送和云端部署沿用暂缓状态。

## 二、技术适配摘要

沿用现有架构，不新建前端项目或独立运营后台。目录、建议、卡片合法性和导航状态都在后端决定；前端只发送受控能力编号/动作并展示结果。状态需跨进程恢复，继续使用现有 SQLite 事务和会话版本，不引入队列或向量库。

## 三、技术栈与模型

Python 3.12.14、已有锁定依赖、Node.js 22.23.2 与原生页面。本轮运行强制 `MODEL_MODE=demo`，真实模型费用为 0。原结构化知识选择模型契约、Prompt、有限重试与初始化错误兜底保留；导航不增加模型调用，不接收模型生成的外链或工具名称。

## 四、环境与配置

复用 `.venv`、`.env.example` 与启动脚本，不读取/回显真实密钥。主验收地址 `http://127.0.0.1:18763`，仅回环访问。使用独立测试数据库，原 `data/bank-demo.sqlite3` 不作为测试对象。目录配置存于 `backend/app/service_catalog.json`，知识沿用 `knowledge.json`；可通过非秘密的 `DEMO_CATALOG_PATH` / `DEMO_KNOWLEDGE_PATH` 指定验收副本，默认仍用原文件。配置是本地维护资料，不提供网络管理或写入接口。

目录与知识在读取/执行时重新校验，配置关闭、失效或变版不要求重启才能阻止下一次动作。测试可注入独立配置路径/知识覆盖，生产默认读取项目受控文件。无法解析目录时普通目录/卡片操作返回安全错误；已有紧急、敏感阻断、人工未接入说明仍可达。不得为验证改动真实配置或原演示数据库。

## 五、项目结构

- `app/services_catalog.py`（或同职责模块）：目录配置校验、建议、公开卡片与导航规则。
- `app/service_catalog.json`：六类能力、启用开关、知识/版本关联、固定问题。具体名称以实现记录为准。
- `app/schemas.py`：卡片、导航、服务视图及操作请求；旧数据兼容默认值。
- `app/db.py`、`alembic/versions/0003_service_navigation.py`：追加导航 JSON，保留旧表与记录。
- `app/main.py`：接口、读取复核、消息/导航事务、版本条件更新和统一错误。
- `app/static/`：最小目录、公开说明/阅读步骤、建议及取消/返回。
- `tests/test_v13.py`、`scripts/verify_restart.py`：新增边界、迁移、恢复/清理；旧测试保留。
- `scripts/verify_browser_v13.mjs` 及相应运行入口：本次独立浏览器检查，V1.2 原脚本和证据保留。

## 六、数据、资产与状态

`conversations` 追加 `navigation` JSON 默认空对象，复用已有 `revision`。导航字段包括状态 `idle/reading/cancelled/invalid`、能力编号、知识编号与版本、公开来源快照摘要 `source_fingerprint`、当前阅读段下标、关联消息编号；对外视图附会话版本。来源摘要用于防止同一版本下正文被修改却沿用旧消息继续阅读，不含客户信息。卡片快照附属于原 `messages.answer`，没有新独立长期存储或点击轨迹。旧消息缺卡片时默认为空。

六个能力逐一绑定原六类知识与版本，个人/企业各三项。新卡片仅允许 `public_info` 或 `reading_steps`；没有官方 URL、金额或私有查询字段。分步内容只拆分同一有效原文，不创作材料或业务步骤。卡片来源显示知识版本、生效区间；页面渲染时间不冒充来源更新时间。

开始/有效同对象公开回答可以建立阅读状态；下一步/返回只移动原文段下标；取消持久化 `cancelled` 并清空普通主题，旧响应不能恢复它。明确新咨询可以开启新主题。未知、敏感、私有查询、人工或紧急回答结束旧普通导航；紧急提示另按既有机制持续。跨对象自由问答仍保留原 V1.2 行为，但不会生成可操作的另一对象目录/卡片，切换对象不能继承私有权限。

前端切换会话/对象时立即撤销旧展示资格，并向旧会话取消旧普通导航；遇到版本冲突先读取最新状态后有限重试，不无限循环。按会话追踪在途取消，快速切回同一会话须先等待该取消再载入历史。取消与消息提交使用同一会话版本条件更新；新版消息请求携带发起时的 `expected_revision`，即使晚于取消才到服务器也须拒绝旧普通任务。原客户端可不传此字段，服务端仍保留提交前版本条件检查。紧急事件仍遵循既有优先保存规则。

知识/能力停用、变版、过期或缺失后，历史文本在许可内保留，卡片标记失效并去掉动作，不能从历史快照恢复业务动作。卡片点击、推荐咨询和普通答复提交前重新核对来源/开关/对象。旧来源在计算期间失效时不提交旧结论，返回统一冲突或不可用错误。

导航与卡片随所属会话自创建起固定 7 天到期，点击/派生记录/刷新不续期；到期读取和操作拒绝，启动及定期清理原会话时一起删除。0003 只追加字段，验证 0001/0002 到新 head 后旧历史和到期时间保留；不删除用户数据。

## 七、API 与数据契约

所有接口保留 `/api/v1` 前缀、归属 Cookie、同源限制和统一错误 `{"error":{"code":"...","message":"..."}}`。无长任务、SSE、上传或银行工具。

| 接口 | 请求 | 响应 | 错误与校验 |
| --- | --- | --- | --- |
| GET `/sessions/{sid}/services` | 归属 Cookie；无正文 | `ServiceView`：`session_revision`、`catalog`、`suggestions`、`navigation`、`cards` | 401 无归属；404 不存在/过期/无权；503 配置/存储暂不可用 |
| POST `/sessions/{sid}/navigation` | `action` 为 start/next/back/cancel；`expected_revision` 严格非负整数；start 须 `capability_id`、`knowledge_version` | 更新后的 `ServiceView`；导航起点可关联保存的公开答复 | 422 结构/动作参数错误；409 CONTEXT_CHANGED、CAPABILITY_CHANGED 或 NAVIGATION_UNAVAILABLE；401/404/503 同上 |
| POST `/sessions/{sid}/messages` | 原 `text` 保持；可选 `expected_revision` 严格非负；建议请求额外传成对的 `capability_id` / `knowledge_version`，文字必须属于该受控建议 | 原 Turn，追加 `services` / `session_revision`；Answer 可含公开 cards | 原错误继续；旧普通请求返回 409 CONTEXT_CHANGED；计算后来源失效返回 409 CAPABILITY_CHANGED；均不保存旧答案 |
| GET `/sessions/{sid}` | 原归属 | 原历史与 session；Answer.cards 可为空；可附当前服务视图 | 原错误；历史卡片读取时重查有效性 |

目录项至少有 `capability_id,title,customer_type,knowledge_id,knowledge_version,status,question`。建议使用受控同主题固定问题，最多 3 条，初始或无适用主题时可为空，不使用画像或无依据的“热门”标签。建议点击与手动咨询复用后端知识与对象检查，不能提交任意工具或 URL。

卡片至少有 `id,kind,capability_id,message_id,customer_type,title,text,source,status,valid,steps,step_index,actions`。`source` 包含 `id,title,version,status,valid_from,valid_until`；必要时提供明确的失效原因。`status` 在本轮仅表达演示可用/不可用，不冒充银行办理状态。动作来自后端白名单。缺来源、来源无正文或对象不适配时不新建卡片结论。

`ServiceView.cards` 为当前导航/当前主题卡片；历史卡由各 `Answer.cards` 表达，读取时取消失效动作。字段结构的最终定义由 Pydantic 与 `/openapi.json` 固化，任何命名调整须同步本文和前端，不改变本表业务语义。

## 八、Prompt 与知识

原 `prompts/select_knowledge.txt` 不变。本轮新能力采用确定性配置与状态规则。六条 `knowledge.json` 的业务正文不为演示卡而扩写；无正式材料时明确无法确认。敏感屏蔽先于存储与模型入口，卡片或建议不能绕过该机制。

## 九、最小验收界面

保留原服务类型、历史、自由问题、示例问题、演示标记及独立紧急提示。增加当前对象的三项目录、明确“演示说明”的公开卡片、分步阅读区、最多三个相关问题及返回/取消。未接入功能只说明状态，不生成外链或可执行查询按钮。

页面所有文本使用安全文字节点，不渲染模型 HTML。以会话编号、会话版本和页面操作代际判断结果是否仍可展示；取消/切换立即撤销旧控件资格。安全提示继续按独立安全版本合并，普通导航不能解除安全提示。请求失败显示限制，可刷新核对，不宣称操作成功。

目标宽度 1440 与 390；按钮可键盘操作、换行不溢出。实际延迟真实演示响应测试取消及切换，不能以伪造模型结果代替。

## 十一、产品经理验收清单

1. Finder 双击项目根目录 `启动演示.command`，保持终端打开，在浏览器打开 `http://127.0.0.1:18763`，看到规则演示及真实模型待验。
2. 选择个人，看到个人开户、存款和贷款三类演示目录；选择企业，看到企业开户、对账回单和融资三类。
3. 点击开户目录，看到演示说明卡及来源版本/有效期；开始分步阅读，点击下一步和返回，内容来自同一演示说明，不承诺材料或办理结果。
4. 点击相关问题，答案仍属于当前主题；点击取消导航，阅读区停止，刷新后仍为取消状态。再次主动选择目录可以开启新的阅读。
5. 普通咨询中切换个人/企业，旧卡片和旧建议不能进入新对象；问“查余额/转人工”仍说明未接入。
6. 问“银行卡被盗刷了”，普通返回/取消、切换和刷新不解除安全提示；只有明确关闭提示才停止显示，且不称风险已解决。
7. 结束时到启动终端按 Control+C，再双击重启；未过期会话和阅读/取消状态可恢复。只使用非敏感演示问题。
