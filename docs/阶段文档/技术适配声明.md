# 技术适配声明

日期：2026-10-02。依据：PRD V1.1、阶段 0 的五项明确确认及通用技术栈手册第一部分。结论与已确认业务范围一致，没有新增费用、外部平台、真实数据或上线范围，因此按默认方案继续，无需重复询问已经确认的决策。

## 1. 产品形态判断
- 产品类型与核心任务：本机银行客服演示，个人和企业公开知识文字咨询，展示来源、未知问题的拒答、紧急与人工路径的接入状态。
- 核心交互：多轮对话；无账户操作、银行查询、投诉提交或真实人工连接。
- 开发路径：后端先行，附最小 HTML 验收工具。首轮检验的是知识来源与状态处理，不开发完整终端信息架构、品牌视觉或正式前端。
- 当前阶段范围：阶段 1 仅形成适配方案；下一阶段实现可启动 API、演示问答、会话持久化及最小验收工具，并实际运行测试。

## 2. 采用的默认方案
- Python 3.12：环境已具备，在项目 `.venv` 内使用，不变更系统 Python。
- FastAPI + Pydantic：接口请求、响应及模型结构化结果统一校验。
- pytest：测试个人/企业知识分流、未知/私有查询降级、敏感输入、错误路径、持久化与到期删除。
- Git：开发开始时初始化仓库，保留原有文档；本轮不提交或推送远端。
- 最小 HTML 验收工具：由同一个后端服务提供文字输入及结果查看，不引入正式前端脚手架，不开启语音或数字人。

## 3. 触发的按需模块
- SQLite + SQLAlchemy + Alembic：会话与消息是多实体关系，并需要历史、到期删除和事务；数据库只在已忽略的本地 `data/` 中，保留迁移脚本，实际验证重启恢复。
- 受控本地知识文件：规模小，按类型、生效时间、状态及关键词筛选；返回演示来源与版本。先不引入向量数据库或付费 Embedding。
- 模型适配边界：本轮运行模式为明确标记的规则演示。预留兼容接口的结构化知识选择适配器，限制超时及重试，严格校验结果；只有未来确认厂商、预算并配置后才启用真实模型。本轮不发出外部模型请求。

## 4. 偏离或暂缓的默认方案
- SSE 暂缓：当前只返回短答案，使用普通请求响应；如以后开启流式输出，必须以 done/error 收尾。
- 正式 Web 前端暂缓：当前 HTML 仅用于本机验收；阶段 3 再按终端和视觉方向形成正式前端，不将本轮界面当作完整前端交付。
- 语音、数字人、银行只读查询、真实人工和投诉接口：按用户明确确认暂缓，完整 PRD 的交付要求保留。任何未接入服务均说明真实状态，不造电话、队列、受理编号和办理成功结果。
- 模型厂商与收费调用：按用户确认暂缓。本轮验证自动化测试及规则服务，真实模型冒烟记为待验，因此阶段 2 不能宣告全部完成。
- 多用户登录与生产部署：本轮仅绑定本机回环地址；本机会话使用不可猜测的会话凭证约束读取，不冒充银行认证。多用户试用及正式上线前另行验收用户隔离。

## 与已确认事项的核对
1. 理解：个人与企业同时覆盖，仅通用银行场景的公开文字咨询演示，符合已确认问题 1、2。
2. 新增项：没有新增收费调用、云平台、真实数据或外部发布，符合已确认问题 3、4、5；安装开源本地依赖不创建收费资源。
3. 暂缓影响：语音、数字人、私有查询、真实人工暂缓，用户已明确确认不作为首轮核心链路验收；完整 PRD 验收继续保留。
